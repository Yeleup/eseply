# Модуль: Дашборд

## Назначение

Дашборд показывает картину выбранной tenant-организации за один расчётный месяц: абонентов, снятие показаний, потребление, начисления, оплаты, долг, динамику по месяцам, прогресс контроллеров и срез по районам.

Дашборд является стартовой страницей панели: корневой маршрут tenant-организации открывает его вместо списка абонентов.

Дашборд реализован классом `App\Filament\Pages\Dashboard`, все агрегаты считает сервис `App\Dashboard\DashboardMetrics`, блоки отрисовывают виджеты `App\Filament\Widgets\Dashboard*`.

## Выбор расчётного месяца

Над блоками находится селектор «Расчётный месяц» со всеми расчётными месяцами организации в виде `08.2026 — Открыт`, свежие сверху.

По умолчанию выбирается текущий открытый или ошибочный расчётный месяц, а если такого нет — последний расчётный месяц организации по дате начала.

Если у организации нет ни одного расчётного месяца, дашборд открывается, но блоки данных не показывают строк.

Идентификатор месяца приходит из состояния Livewire и может быть подменён, поэтому принимается только месяц текущей организации; любое другое значение приводит к выбору месяца по умолчанию.

Над блоками показывается общая плашка состояния расчётного месяца: «Расчётный месяц не открыт» и «Расчётный месяц закрывается».

## Источник начислений

Начисление создаётся только при закрытии месяца, а квитанция появляется по ходу открытого месяца при вводе показания. Поэтому источник денежных показателей зависит от статуса выбранного месяца.

| Показатель | Месяц `closed` | Месяц `open`, `processing`, `failed` |
| --- | --- | --- |
| Начислено | сумма начислений | сумма квитанций |
| Долг на конец месяца | сумма положительных конечных сальдо начислений | сумма положительных конечных сальдо квитанций |
| Абонентов с долгом | количество начислений с положительным конечным сальдо | количество квитанций с положительным конечным сальдо |
| Оплачено | сумма оплат месяца | сумма оплат месяца |

Для незакрытого месяца начисление считается предварительным: квитанции есть только у абонентов, по которым уже сняли показание. Плитка «Начислено» в этом случае подписывается «предварительно, по N квитанциям».

Процент сбора равен отношению оплаченного к начисленному и равен нулю при нулевом начислении.

## Плитки

| Плитка | Значение | Описание |
| --- | --- | --- |
| Абоненты | количество активных абонентов | всего N · новых за месяц M |
| Счётчики | количество активных счётчиков активных абонентов | по счётчику N |
| Снято показаний | процент снятия | N из M |
| Потребление | сумма расхода за месяц | за выбранный месяц, единица измерения услуги организации |
| Начислено | сумма | по N начислениям, для незакрытого месяца — «предварительно, по N квитанциям» |
| Оплачено | сумма | N оплат · сбор P % |
| Долг на конец месяца | сумма | N абонентов |

Новым считается абонент, созданный внутри календарного месяца выбранного расчётного месяца.

В знаменатель процента снятия входят активные счётчики активных абонентов с типом начисления «по счётчику», в числитель — те из них, по которым есть показание за выбранный месяц. При нулевом знаменателе процент равен нулю.

Цвет плитки «Снято показаний»: меньше 70 % — красный, меньше 95 % — жёлтый, иначе зелёный.

## График начислений и оплат

Столбчатая диаграмма показывает начисления и оплаты за последние 12 расчётных месяцев организации, от старого месяца к новому.

Начисление каждого месяца берётся по правилу источника начислений: для закрытого месяца — из начислений, для остальных — из квитанций.

## Прогресс снятия по контроллерам

Таблица показывает контроллера, всего счётчиков, снято, не снято и процент снятия.

Зона ответственности определяется назначенными районами и улицами. Счётчик, попадающий к контроллеру одновременно по району и по улице, учитывается один раз. Контроллер без назначенной зоны получает нули.

Строки отсортированы по проценту снятия по возрастанию — отстающие сверху. Показывается не больше 10 строк, полный список остаётся в отчёте «Процент снятия по контроллерам».

Правило зоны реализовано общим классом `App\Support\ControllerZoneMeterCounts`, которым пользуется и отчёт, и дашборд.

## Срез по районам

Таблица показывает район с городом, количество активных абонентов, процент снятия, начислено, оплачено и долг.

Районы без активных абонентов в таблицу не попадают.

Строки отсортированы по долгу по убыванию. Показывается не больше 10 строк, полный список остаётся в отчёте «Отчёт по долгам».

## Доступ

| Блок | Оператор | Контроллер |
| --- | --- | --- |
| Плитки «Абоненты», «Счётчики», «Снято показаний», «Потребление» | вся организация | своя зона ответственности |
| Плитки «Начислено», «Оплачено», «Долг на конец месяца» | видит | скрыты |
| График начислений и оплат | видит | скрыт |
| Прогресс снятия по контроллерам | все контроллеры организации | только своя строка |
| Срез по районам | видит | скрыт |

Денежные блоки скрываются проверкой роли на уровне виджета, а не вёрсткой, поэтому денежные запросы для контроллера не выполняются вовсе.

Пользователь, не являющийся участником организации, не проходит tenant-проверку панели и до дашборда не доходит.

## Пустые состояния

- У организации нет расчётных месяцев — блоки не показывают строк, плашка предлагает открыть расчётный месяц.
- За выбранный месяц нет данных — плитки показывают нули, таблицы показывают пустое состояние, график не рисует столбцы.
- В организации нет контроллеров — таблица прогресса показывает «Нет контроллеров».
- В районах нет активных абонентов — срез по районам показывает «Нет данных по районам».
- У контроллера нет назначенной зоны — плитки и строка прогресса показывают нули.

## Производительность

Каждый блок считает свои показатели агрегатными запросами без загрузки моделей и без запросов в цикле. Срез по районам строится одним запросом с коррелированными подзапросами, динамика по месяцам — тремя сгруппированными запросами.

Кэш не используется: цифры дашборда должны совпадать с отчётами в тот же момент времени.
