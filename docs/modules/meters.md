# Модуль: Счётчики

## Терминология

Счётчик в коде называется `Meter`.

Показание счётчика в коде называется `MeterReading`.

Таблица счётчиков называется `meters`.

Таблица показаний счётчиков называется `meter_readings`.

## Назначение

Модуль хранит счётчики абонентов и помесячные показания по ним.

Показания используются при закрытии месяца для клиентов с `billing_type = meter`.

## Основные поля счётчика

| Поле | Описание |
|---|---|
| Организация | Tenant-организация, поле `organization_id` |
| Абонент | Клиент, поле `client_id` |
| Услуга | Услуга выбранной tenant-организации, поле `utility_service_id` если хранится технически |
| Номер | Номер счётчика, поле `number` |
| Дата установки | Дата установки счётчика, поле `installed_on` |
| Начальное показание | Целое показание на момент установки, поле `initial_reading` |
| Дата снятия | Дата отправки счётчика в архив, поле `removed_on` |
| Статус | Активный / в архиве, поле `status` |
| Примечание | Дополнительная информация, поле `note` |

## Основные поля показания

| Поле | Описание |
|---|---|
| Организация | Tenant-организация, поле `organization_id` |
| Счётчик | Счётчик, поле `meter_id` |
| Абонент | Клиент, поле `client_id` |
| Услуга | Услуга выбранной tenant-организации, поле `utility_service_id` если хранится технически |
| Расчётный месяц | Связь с `BillingPeriod`, поле `billing_period_id` |
| Предыдущее показание | Целое значение на начало периода, поле `previous_reading` |
| Текущее показание | Целое значение на конец периода, поле `current_reading`; пустое значение означает визит без снятого показания |
| Расход | Целая разница текущего и предыдущего показания, поле `consumption` |
| Дата ввода | Дата внесения показания, поле `read_at` |
| Примечание | Дополнительная информация, поле `note` |
| Фото | Необязательное фото счётчика, поле `photo_path` (путь к файлу на диске `public`) |

## Правила

Счётчик относится к tenant-организации и абоненту, а коммунальная услуга берётся из tenant-организации.

Номер счётчика уникален внутри tenant-организации.

У одного абонента может быть несколько активных счётчиков.

Каждый активный счётчик абонента участвует в расчёте по счётчику.

Снятые счётчики сохраняются для истории.

Дата снятия не редактируется вручную в форме счётчика.

Начальное показание задаётся только при создании счётчика и не изменяется после сохранения.

Начальное показание, предыдущее показание, текущее показание и расход хранятся целыми числами: поля `meters.initial_reading`, `meter_readings.previous_reading`, `meter_readings.current_reading` и `meter_readings.consumption` имеют целочисленный тип.

Формы ввода показаний и начального показания принимают только целые числа; дробное значение, пришедшее в обход формы, округляется до целого при сохранении.

Показания и расход выводятся без дробной части во всех таблицах, карточке абонента, квитанции и отчётах, включая XLSX-выгрузки.

Чтобы снять счётчик с активного учёта, оператор использует действие «Отправить в архив».

Действие «Отправить в архив» требует подтверждения, проставляет `removed_on` текущей датой и переводит `status` в `removed`.

Чтобы вернуть счётчик в активный учёт, оператор использует действие «Вывести из архива».

Действие «Вывести из архива» требует подтверждения, очищает `removed_on` и переводит `status` в `active`.

Одно показание хранится только один раз по связке `meter_id + billing_period_id`.

Если показание за текущий расчётный месяц уже есть, оператор должен изменить существующее показание вместо создания нового.

Одинаковый расчётный месяц может использоваться для разных счётчиков.

При создании показания расчётный месяц не выбирается оператором.

Система автоматически привязывает показание к текущему расчётному месяцу tenant-организации в статусе `open` или `failed`.

Показание можно создать, изменить или удалить только в расчётном месяце со статусом `open` или `failed`.

В закрытом расчётном месяце показания менять нельзя.

Основной ввод показаний выполняется внутри карточки счётчика через связанную таблицу `readings` или быстрым действием у счётчика в карточке абонента.

Массовый ввод показаний выполняется на отдельной странице «Ввод показаний»: контроллер выбирает город, район и улицу и вводит текущее показание прямо в строке списка активных счётчиков. Модуль описан в `docs/modules/meter-reading-entry.md`.

Показание на странице «Ввод показаний» сохраняется по одной строке при уходе из поля или по нажатию Enter; отдельной кнопки сохранения всего списка нет.

В карточке абонента быстрое действие называется «Добавить показание», если за текущий расчётный месяц показания ещё нет.

В карточке абонента быстрое действие называется «Изменить показание», если за текущий расчётный месяц показание уже существует, и обновляет найденную запись.

Для контроллера списки счётчиков и показаний ограничиваются назначенными регионами и улицами через адрес абонента.

Контроллер может просматривать страницу счётчика из своей зоны ответственности как контекст для ввода показаний.

Контроллер не создаёт, не редактирует, не архивирует, не выводит из архива и не удаляет счётчики.

Контроллер может вводить и изменять показания только по счётчикам абонентов своей зоны ответственности.

Контроллер не может сохранить показание меньше предыдущего; в такой ситуации показание вводит оператор.

Удаление показаний доступно только оператору.

К показанию можно прикрепить одно необязательное фото счётчика.

Фото загружается через поле формы показания. На телефоне и планшете поле показывает две кнопки: «Сделать фото» открывает камеру, «Из галереи» — обычный выбор файла. На компьютере кнопок нет, остаётся обычная область загрузки.

Исходный снимок принимается размером до 25 МБ и перед отправкой сжимается в браузере до 1920px, поэтому на диск попадают сотни килобайт.

Файлы фото хранятся на диске `public` в каталоге `meter-reading-photos/{organization_id}`.

Поле фото защищено от подмены пути: если вместо загруженного файла в форму подставлена строка пути, путь принимается только когда он ведёт в каталог `meter-reading-photos/{organization_id}` текущей организации, такой `photo_path` уже принадлежит существующему показанию этой организации И это показание относится к тому же счётчику, для которого сохраняется форма; иначе форма отклоняет значение.

При загрузке нового фото прежний файл удаляется с диска.

При удалении показания файл фото удаляется с диска.

При удалении счётчика файлы фото всех его показаний удаляются с диска.

При удалении организации каталог фото показаний этой организации удаляется целиком.

При создании показания поле `previous_reading` заполняется системой автоматически.

Для первого показания используется `meters.initial_reading`.

Для следующих расчётных месяцев используется последнее `meter_readings.current_reading` этого счётчика за месяц раньше текущего расчётного месяца.

Расход считается по формуле:

`consumption = current_reading - previous_reading`

Если текущее показание меньше предыдущего, расход получается отрицательным.

Показание меньше предыдущего сохраняет только оператор: контроллеру форма отклоняет такое значение с подсказкой, что при перекруте табло или замене счётчика показание вводит оператор.

Оператор может заменить счётчик и поправить начисление, поэтому ограничение снято именно с него.

Показание, равное предыдущему, разрешено всем: нулевой расход — нормальная ситуация и закрытию месяца не мешает.

Текущее показание ограничено сверху значением `99999` во всех формах и действиях ввода: странице «Ввод показаний», форме ресурса, связанной таблице показаний и быстром действии в карточке абонента. Ограничение проверяется на сервере при сохранении.

Контроллёр подтверждает расход, строго превышающий три средних расхода конкретного счётчика. Среднее берётся по `consumption` снятых показаний (`current_reading` не пусто) за три непосредственно предшествующих расчётных месяца; отрицательные расходы исключаются. Для одного или двух подходящих месяцев используется их среднее. Диалог не показывается, если подходящей истории нет, среднее равно нулю или расход равен тройному среднему. В диалоге видны введённое показание, расход и среднее; отмена не меняет существующее показание и не создаёт новое, а в массовом вводе сохраняемое в поле значение отмечается как не сохранённое. Оператор не получает диалог.

Ограничение действует во всех формах показания: в связанной таблице показаний счётчика, в быстром действии у счётчика в карточке абонента, в форме создания и изменения показания и на странице «Ввод показаний».

Показание, уже сохранённое ниже предыдущего оператором, контроллер может пересохранить без изменения значения — чтобы приложить фото, примечание или дату, — но опустить его ещё ниже не может.

Минимально допустимое показание вычисляется на сервере из предыдущего показания и роли участника, а не из поля формы.

Сохранённый отрицательный расход остаётся заметным: при массовом вводе строка подсвечивается предупреждением и система показывает уведомление об отрицательном расходе.

Без отдельного подтверждения оператора закрыть месяц с отрицательным расходом нельзя: закрытие останавливается с ошибкой `negative_meter_consumption` по всей организации, поэтому такие показания нужно исправить или подтвердить на странице ошибок.

При сохранении показания `organization_id` и `client_id` берутся из выбранного счётчика.

Если `utility_service_id` хранится в счётчике или показании, он должен совпадать с услугой выбранной tenant-организации.

При закрытии месяца начисление по счётчику считается по формуле:

`amount = сумма consumption по всем активным счётчикам абонента * unit_price`

Если для активного клиента с `billing_type = meter` нет активных счётчиков по услуге организации или нет показания за период хотя бы по одному активному счётчику, начисление не создаётся и процесс закрытия месяца показывает ошибку.

Запись с пустым текущим показанием считается отсутствующим показанием: она не закрывает месяц, а её примечание добавляется к тексту ошибки `missing_meter_reading`, чтобы оператор видел причину.

## Административная панель

Счётчики управляются через Filament resource `MeterResource` внутри выбранной tenant-организации.

Основной список счётчиков абонента отображается в карточке клиента через связанную таблицу `meters`.

В связанной таблице `meters` у каждого счётчика доступно быстрое действие показания без перехода в карточку счётчика.

Если в текущем расчётном месяце показания по счётчику ещё нет, действие отображается как «Добавить показание» и создаёт новую запись.

Если в текущем расчётном месяце показание по счётчику уже есть, действие отображается как «Изменить показание» и обновляет существующую запись.

Для контроллера быстрое действие показания доступно только по счётчикам из его зоны ответственности.

Показания управляются внутри `MeterResource` как связанная таблица показаний конкретного счётчика.

Массовый ввод показаний вынесен на отдельную страницу `App\Filament\Pages\MeterReadingEntry` в группе навигации «Учёт»; она доступна оператору и контроллеру, и контроллер видит на ней только счётчики своей зоны ответственности.

Страница «Ввод показаний» адаптивная: от 640px строки показываются плотной таблицей, на телефоне каждая строка превращается в карточку с крупным полем ввода и цифровой клавиатурой.

Отдельный раздел «Счётчики» не является основным рабочим сценарием; оператор открывает счётчик из карточки клиента.

Форма создания счётчика должна позволять выбрать абонента, номер, дату установки, начальное показание и примечание.

Дата установки в форме создания счётчика по умолчанию равна текущей дате.

Форма редактирования счётчика должна показывать начальное показание без возможности изменения.

Форма счётчика доступна контроллеру только для просмотра, без сохранения изменений.

Дата снятия и статус архива управляются только действиями «Отправить в архив» и «Вывести из архива».

Форма показания внутри счётчика должна позволять указать текущее показание, дату ввода, примечание и фото счётчика.

Предыдущее показание в форме показания должно быть уже заполнено и не должно требовать ручного ввода.

В связанной таблице показаний должны отображаться период, предыдущее показание, текущее показание, расход, дата ввода и миниатюра фото; клик по миниатюре открывает фото в полный размер.


### Принятие показаний при закрытии

На странице ошибок закрытия оператор может принять отдельный счётчик или все показания выбранного вида во всём месяце (независимо от фильтров и страницы отчёта):

- «Принять пропущенные показания»: последнее известное показание до месяца, либо начальное показание, переносится в текущий месяц с нулевым расходом. Уже введённые значения не перезаписываются. Фото и примечание визита сохраняются, дата снятия не выдумывается.
- «Принять отрицательный расход»: оператор отдельно подтверждает ошибку; текущие и предыдущие показания и отрицательный расход остаются без изменений. При закрытии такой расход уменьшает начисление и задолженность, в том числе может дать отрицательную сумму начисления.

Массовое принятие пропущенных показаний и отрицательного расхода выполняется фоновой задачей `AcceptBillingClosureMeterReadingsJob`. HTTP-запрос только ставит задачу в очередь; оператор получает уведомление с количеством принятых показаний либо уведомление об ошибке. Принятие одной строки остаётся синхронным. До завершения массового принятия повторное принятие (включая отдельную строку) и запуск закрытия этого месяца отклоняются с сообщением о необходимости дождаться операции. После завершения оператор запускает закрытие месяца вручную; чтобы увидеть обновлённый отчёт после уведомления, страницу ошибок нужно открыть заново: во время массового принятия страница не опрашивает сервер.

Задача повторно проверяет полномочия оператора, принадлежность и редактируемость месяца. Изменения показаний и удаление ошибок выполняются в одной транзакции; при ошибке обработки изменения откатываются. Резервирование освобождается при завершении, ошибке постановки в очередь или отказе задачи. Резервирование имеет защитный срок 3600 секунд; задача с лимитом 1800 секунд не начинает обработку, если оставшегося срока недостаточно. Просроченную операцию нужно запустить повторно.


Подтверждение требует согласия в диалоге и сохраняет код причины, оператора и время в показании. Изменение значений показаний, счётчика или расчётного месяца сбрасывает подтверждение; изменение примечания или фотографии его сохраняет. Контролёр подтверждать ошибки не может. Обработка доступна только для редактируемого месяца своей организации и блокирует строку месяца на время транзакции.

Массовое действие обрабатывает все активные счётчики активных абонентов с начислением по счётчику, включая следующие счётчики абонента, ещё не попавшие в отчёт. После обработки можно запустить «Закрыть месяц» прямо на странице ошибок. Закрытие повторно проверяет все данные; другие ошибки продолжают блокировать месяц.
