# Модуль: Квитанции

## Терминология

Квитанция в коде называется `Receipt`.

Таблица квитанций называется `receipts`.

## Назначение

Модуль хранит квитанции абонентов за расчётный месяц.

Квитанция создаётся автоматически при сохранении показания счётчика `MeterReading`.

Если показание счётчика за тот же расчётный месяц изменяется, существующая квитанция этого абонента и периода обновляется.

Квитанция не хранит обязательную информацию о начислении клиента и не создаётся закрытием месяца из `Accrual`.

## Основные поля

| Поле | Описание |
|---|---|
| Организация | Tenant-организация, поле `organization_id` |
| Абонент | Клиент, поле `client_id` |
| Расчётный месяц | Связь с `BillingPeriod`, поле `billing_period_id` |
| Начисление | Необязательная техническая ссылка для старых данных, поле `accrual_id` |
| Номер квитанции | Уникальный номер внутри организации, поле `receipt_number` |
| Лицевой счёт | Снимок лицевого счёта абонента, поле `account_number` |
| Абонент | Снимок имени / наименования абонента, поле `client_name` |
| Название услуги | Снимок услуги организации, поле `utility_service_name` |
| Тип расчёта | Тип расчёта абонента, поле `billing_type` |
| Объём | Суммарный расход по показаниям счётчиков абонента за период, поле `volume` |
| Тариф | Использованная цена за единицу, поле `tariff_price` |
| Сумма | Сумма к оплате по показаниям и тарифу, поле `amount` |
| Список счётчиков | Строки показаний счётчиков абонента за период: номер счётчика, предыдущее показание, текущее показание, расход, тариф и сумма; показания и расход выводятся целыми числами |
| Оплачено | Сохранённая сумма оплат, поле `paid_amount` |
| Корректировка | Сохранённая сумма корректировок сальдо, поле `adjustment_amount` |
| Начальное сальдо | Сохранённое начальное сальдо, поле `opening_balance` |
| Конечное сальдо | Сохранённое конечное сальдо, поле `closing_balance` |
| Дата формирования | Когда квитанция была сформирована или обновлена, поле `issued_at` |

## Правила

Квитанция формируется по одному абоненту за один расчётный период.

Один абонент не может иметь две квитанции за один расчётный месяц.

Номер квитанции формируется как `код расчётного месяца-account_number`, например `202605-100001`.

При создании показания счётчика система создаёт квитанцию для абонента и расчётного месяца показания.

При изменении показания счётчика система обновляет ту же квитанцию, а не создаёт новую.

Если за текущий расчётный месяц у абонента уже есть квитанция, создание, изменение или удаление оплаты обновляет в ней сумму оплат и конечное сальдо.

Если квитанции за расчётный месяц ещё нет, оплата не создаёт её.

Если за период у абонента есть несколько счётчиков, квитанция хранит суммарный расход по всем показаниям абонента за этот период.

Начальное сальдо квитанции — конечное сальдо предыдущей квитанции абонента плюс входящие остатки (корректировки типа `opening_balance`) за расчётный месяц квитанции.

В сумму корректировок квитанции входящие остатки не входят: они уже учтены в начальном сальдо.

В просмотре и печатной форме квитанция должна показывать список счётчиков с показаниями, расходом, тарифом и суммой по каждой строке.

Закрытие месяца создаёт `Accrual`, но не создаёт и не обновляет `Receipt`.

Квитанция создаётся только моделью `MeterReading`, поэтому массовая загрузка показаний напрямую в таблицу оставляет организацию без квитанций: дашборд не показывает предварительного начисления за незакрытый месяц, а оборотно-сальдовая ведомость читает период как пустой.

## Пересбор квитанций

Команда `receipts:rebuild` пересобирает квитанции по уже сохранённым показаниям счётчиков.

Команда применяется после массовой загрузки показаний и после исправления данных, из-за которых квитанции сохранились с нулевой суммой, например после переустановки услуги организации.

Расчёт целиком берётся из `Receipt::fromMeterReading()`, поэтому пересобранная квитанция совпадает с квитанцией, созданной при обычном вводе показания: объём, тариф, сумма, начальное сальдо, оплаты, корректировки и конечное сальдо считаются по текущим данным периода.

| Параметр | Описание |
|---|---|
| `--organization` | Идентификатор организации; по умолчанию все организации |
| `--period` | Код расчётного месяца в формате `ГГГГММ`, например `202608`; по умолчанию все месяцы |
| `--chunk` | Сколько показаний читать за один проход, по умолчанию 500 |

Квитанция пересобирается один раз на пару «абонент и расчётный месяц», даже если у абонента несколько счётчиков.

Команда не создаёт квитанции абонентам без показаний за период: у абонентов с фиксированной суммой и с расчётом на одного человека квитанции по-прежнему нет до закрытия месяца.

Команда не меняет квитанции организаций и периодов вне заданных параметров.

Повторное закрытие закрытого расчётного месяца запрещено.

Печатная форма квитанции строится по HTML-шаблону организации с плейсхолдерами `{{переменная}}` (модуль «Шаблон квитанции», `docs/modules/receipt-template.md`). Шаблон редактируется визуальным конструктором; если он не настроен, используется стандартный шаблон: два экземпляра на листе, шапка, абонент и реквизиты, таблица счётчиков, итоги.

## Административная панель

Квитанции отображаются внутри карточки абонента через связанную таблицу квитанций и в отдельном resource-разделе «Квитанции».

Раздел «Квитанции» отображается в навигации административной панели и используется для просмотра, фильтрации и массовой печати уже сформированных квитанций.

Оператор может открыть карточку абонента, увидеть его квитанции, фильтровать их по периоду и просматривать квитанцию.

На странице просмотра квитанции оператор может нажать «Печатать PDF», чтобы открыть печатное представление квитанции в новой вкладке и сохранить или распечатать его через браузерный PDF-диалог.

В разделе «Квитанции» оператор может фильтровать квитанции по периоду, региону, улице, контроллеру и флажку «К оплате больше 0», выбрать нужные строки и выполнить bulk-действие «Печатать выбранные». Флажок оставляет только квитанции с положительным конечным сальдо: в печатной форме именно из него считается сумма к оплате.

«Печатать выбранные» печатает ровно те строки, которые отмечены в момент нажатия, включая «Выбрать все» по всем страницам за вычетом снятых строк. Действие отправляет актуальный выбор на сервер, сохраняет id выбранных квитанций в кэше под случайным токеном на 30 минут и открывает массовую печать `print-bulk?selection=<токен>` в новой вкладке; если браузер заблокировал вкладку, её можно открыть кнопкой «Открыть» в уведомлении. После действия выбор строк снимается. Id квитанций в адресе печати не передаются, прежний параметр `receipt_ids` не поддерживается.

Одна печать выбранных строк ограничена общим пределом массовой печати — 10 000 квитанций (`receipts.print_selection_limit`, см. ниже). Предел проверяется дважды: bulk-действие читает не больше предела плюс одного id и при большем выборе не открывает печать — оператор видит уведомление «Выбрано больше 10 000 квитанций» с предложением сузить выбор или воспользоваться «Печатать по фильтру», а отмеченные строки остаются отмеченными (выбор снимается только после успешного открытия печати); страница печати по токену тоже не печатает выборку больше предела.

Токен выбора многоразовый в пределах 30 минут: владелец может обновить вкладку печати или открыть её повторно по ссылке из уведомления. Токен открывается только тем же пользователем в той же организации: другой пользователь, другая организация, неизвестный или просроченный токен дают 404, как и выбор, в котором есть квитанции другой организации или удалённые квитанции. Токен не расширяет доступ: по нему печатаются только квитанции, которые владелец и так может напечатать в своей организации.

В строках таблицы раздела «Квитанции» нет стандартного действия просмотра; доступно отдельное действие «Печать».

Если в разделе «Квитанции» выбран фильтр периода, региона, улицы или контроллера, оператор видит кнопку «Печатать по фильтру», которая открывает массовую печать всех квитанций текущего tenant по текущим выбранным фильтрам. Флажок «К оплате больше 0» сам по себе не открывает массовую печать: он сужает её, когда выбран хотя бы один из этих фильтров. При включённом флажке в печать не попадают квитанции с нулевым или отрицательным конечным сальдо.

Фильтр контроллера печатает квитанции абонентов из зоны ответственности выбранного контроллера по его назначенным регионам и улицам.

Кнопка «Печатать по фильтру» не отображается, пока не выбран хотя бы один фильтр.

Массовая печать сортирует квитанции по лицевому счёту и номеру квитанции; последним ключом сортировки идёт id квитанции, поэтому порядок однозначен.

Массовая печать раскладывает экземпляры квитанций на листы A4 сеткой 2×4 — до 8 экземпляров на листе, с пунктирными линиями отреза. При шаблоне с одним экземпляром на лист это 8 квитанций на A4, при шаблоне с двумя экземплярами (для организации и для абонента) — 4 квитанции, причём оба экземпляра одной квитанции всегда попадают на один лист. Экземпляр вёрстается в ширину половины A5 и уменьшается до ячейки (масштаб 0.7), поэтому шаблон организации не меняется. Печать одной квитанции по-прежнему выводит лист A5.

Если по выбранным фильтрам нет сформированных квитанций, массовое печатное представление показывает пустое состояние и не запускает диалог печати.

В одну массовую печать попадает не больше 10 000 квитанций (настройка `receipts.print_selection_limit`, переменная окружения `RECEIPT_PRINT_SELECTION_LIMIT`). Предел общий для «Печатать выбранные» и «Печатать по фильтру». Если выборка больше предела, печатное представление не выводит квитанции и не запускает диалог печати, а показывает сообщение «Слишком много квитанций для одной печати» с числом найденных квитанций и пределом и просит сузить фильтры (регион, улица, контроллер) или отметить меньше квитанций и печатать частями; ответ имеет статус 422. Выборка ровно из предела печатается.

Массовая печать отдаётся потоком: квитанции загружаются и отрисовываются порциями по 200 (порция занимает целое число листов A4), строки счётчиков порции загружаются пакетно, поэтому число запросов к базе растёт с числом порций, а не квитанций, а память запроса от размера выборки почти не зависит. Замер на 10 000 квитанциях одного периода: 258 запросов, около 21 МБ памяти, около 5 секунд; на 20 000 — 508 запросов, около 30 МБ, около 9 секунд. Предел ограничивает прежде всего объём страницы в браузере: 10 000 квитанций — около 85 МБ HTML и до 5 000 листов A4.

Доступ, предел, состав выборки и шаблон проверяются до начала ответа. Каждая порция снова загружается только из квитанций текущей организации; строки счётчиков порции отбираются по точным парам «расчётный месяц — абоненты этого месяца». Если после начала выдачи порция не загрузилась полностью (например, квитанцию удалили или перенесли в другую организацию во время печати) или не отрисовалась, ошибка записывается в лог, а страница закрывается состоянием «Печать прервана»: уже выведенные листы и кнопка «Печатать PDF» скрываются, автоматическая печать не запускается; сообщение об ошибке видно только на экране, поэтому при ручной печати ничего не печатается.

Массовая печать не создаёт новые квитанции, не обновляет существующие квитанции и не пересчитывает суммы.

Печатное представление использует сохранённые поля `Receipt` для вывода сумм и не показывает обязательную информацию о начислении клиента.

Ручное создание и редактирование квитанций в первом этапе не используется.
