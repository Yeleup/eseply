# Модуль: Отчёты

## Назначение

Модуль предоставляет отчёты по сохранённым данным выбранной tenant-организации.

Отчёты открываются отдельным разделом Filament «Отчёты» и не размещаются внутри карточки абонента.

## Архитектура

Один отчёт реализуется отдельным классом в `app/Reports`.

Доступные отчёты регистрируются в `App\Reports\ReportRegistry`.

Filament-страницы отвечают за навигацию и отображение, а запросы и колонки отчёта находятся в классе конкретного отчёта.

Кроме готовых отчётов есть конструктор разовых отчётов — см. раздел «Конструктор отчётов». Его источники данных живут в `app/Reports/Builder` и регистрируются в `App\Reports\Builder\ReportSourceRegistry`, а не в `ReportRegistry`.

## Сводный режим

Каждый зарегистрированный отчёт поддерживает детальный режим и сводный режим.

Сводный режим строится на странице просмотра отчёта и группирует строки отчёта:

- по городам;
- по районам;
- по улицам;
- по контроллерам.

Сводка использует тот же tenant-scope, тот же расчётный месяц и те же ограничения доступа контроллера, что и детальный отчёт.

Группировка по городам присоединяет район строки отчёта к его городу, поэтому базовые запросы отчётов для неё не меняются. Строка без района попадает в группу «Без города».

Для контроллера сводка показывает только строки отчёта по абонентам из назначенных ему регионов и улиц.

В сводке по контроллерам строка отчёта попадает в строку каждого контроллера, чья зона ответственности подходит абоненту по району или улице.

Если один и тот же контроллер подходит абоненту одновременно по району и улице, внутри строки этого контроллера строка отчёта учитывается один раз.

Сводный режим показывает количество уникальных абонентов и профильные показатели конкретного отчёта: суммы оплат, начисления, долг, потребление, количество счётчиков, установок, снятий или процент снятия.

Колонки «Строк» в сводке нет ни в одном отчёте — ни на экране, ни в XLSX-выгрузке, ни в одной группировке. Количество строк либо повторяло «Абонентов», либо профильный счётчик самого отчёта («Счётчиков», «Не снято счётчиков», «Всего счётчиков», «Новых лицевых счетов», «Оплат», «Неоплаченных квитанций», «Показаний»), поэтому колонка ничего не добавляла.

Последняя строка сводки — «Итого». Суммируемые показатели складываются, вычисляемые — «Не снято» и «Процент снятия» — пересчитываются от итоговых значений, а не суммируются.

В сводке по контроллерам абонент из пересекающихся зон попадает в строку каждого подходящего контроллера, поэтому «Итого» повторяет сумму видимых строк таблицы, а не число уникальных абонентов.

Если на странице открыт сводный режим, XLSX-выгрузка скачивает сводный отчёт по выбранной группировке вместе со строкой «Итого». Если открыт детальный режим, XLSX-выгрузка скачивает детальный отчёт.

Показания счётчиков, начальное показание и потребление выводятся целыми числами и в экранных таблицах отчётов, и в XLSX-выгрузках, включая сводный показатель «Потребление».

## Выбор расчётного месяца

Обычный отчёт строится за текущий открытый или ошибочный расчётный месяц.

Отчёт, реализующий контракт `App\Reports\Contracts\SelectsBillingPeriod`, строится за расчётный месяц, выбранный оператором.

У такого отчёта на странице появляется действие «Расчётный месяц» со списком всех расчётных месяцев организации и их статусов.

Выбранный расчётный месяц хранится в параметре адреса `period`, сохраняется при переключении детального и сводного режимов и используется XLSX-выгрузкой.

Идентификатор из адреса принимается, только если это положительное целое число и расчётный месяц принадлежит выбранной tenant-организации. Иначе используется расчётный месяц по умолчанию.

Контракт реализует «Оборотно-сальдовая ведомость». Остальные отчёты его не реализуют, и действие «Расчётный месяц» у них не отображается.

## Фильтры по датам

Каждая колонка даты в детальном режиме отчёта имеет фильтр диапазона дат с полями «с» (`start_date`) и «по» (`end_date`).

Фильтры реализованы общим классом `App\Filament\Support\DateRangeFilter`.

Правила работы фильтра:

- обе границы включительны;
- сравнение выполняется по дате: у колонок с датой и временем время при фильтрации не учитывается;
- каждую границу можно указать отдельно — фильтр работает и только с начальной, и только с конечной датой;
- строки с пустой датой не попадают в результат, пока фильтр по этой дате активен;
- некорректное значение границы (не строка или не дата) игнорируется и не применяется к запросу;
- активный фильтр показывает индикатор над таблицей; каждая граница снимается своим индикатором отдельно.

Фильтры по датам действуют на экранную таблицу детального режима. Сводный режим их не учитывает. Исключение — конструктор отчётов: там фильтры действуют и в сводке (см. «Конструктор отчётов»).

XLSX-выгрузка детального режима повторяет все применённые фильтры отчёта, включая фильтры по датам: все отчёты с фильтрами по датам реализуют контракт `App\Reports\Contracts\FiltersExcelExport` (см. раздел «Фильтры по адресу и контроллерам»). XLSX-выгрузка сводного режима фильтры не учитывает.

Поиск по таблице в XLSX-выгрузку не попадает ни в одном отчёте.

Фильтры по отчётам:

- Ведомость снятия показаний — дата установки счётчика;
- Список не снятых показаний — дата установки счётчика;
- Новые лицевые счета — дата создания абонента;
- Отчёт по оплатам — дата оплаты;
- Отчёт по неоплаченным — дата формирования квитанции;
- Замена/установка счётчика — дата установки и дата снятия (два независимых фильтра);
- Отчёт по потреблениям — дата снятия показания.

Отчёты «Процент снятия по контроллерам», «Отчёт по долгам» и «Оборотно-сальдовая ведомость» не содержат колонок дат и фильтров по датам не имеют.

## Фильтры по адресу и контроллерам

Фильтр по адресу реализован общим классом `App\Filament\Support\ClientAddressFilter`, фильтр по контроллерам — `App\Filament\Support\ControllerZoneFilter`.

Фильтр по адресу состоит из трёх каскадных полей одного фильтра:

- «Город» — один город организации;
- «Район» — один район; список сужается выбранным городом, без выбранного города показывает все районы организации в виде «Город / Район»;
- «Улицы» — несколько улиц; при выбранном районе показывает улицы этого района, при выбранном только городе — улицы этого города, без выбора — все улицы организации. Пока район не выбран, улицы показываются в виде «Район / Улица».

Правила работы фильтра по адресу:

- смена города очищает выбранные район и улицы, смена района очищает выбранные улицы;
- каждое поле применяется независимо: можно выбрать только улицы, не выбирая город и район;
- пустое поле фильтр не применяет;
- каждое заполненное поле показывает свой индикатор над таблицей и снимается отдельно.

Фильтр по контроллерам выбирает несколько контроллеров текущей организации. Строка отчёта остаётся, если абонент попадает в зону ответственности хотя бы одного выбранного контроллера, то есть совпадает с назначенным контроллеру районом или назначенной улицей. Абонент, попадающий в зоны нескольких выбранных контроллеров, остаётся одной строкой.

Фильтр по контроллерам доступен всем ролям. Для контроллера он не расширяет видимость: строки в любом случае ограничены его собственной зоной, поэтому выбор чужого контроллера оставляет только пересечение зон.

Значения фильтров приходят из состояния Livewire и могут быть подменены, поэтому фильтр принимает только положительные целые идентификаторы, а контроллером считается только участник текущей организации с ролью контроллера. Подмена значения не расширяет видимость: фильтр умеет только сужать запрос, который уже ограничен зоной текущего пользователя.

Фильтры по адресу и контроллерам есть в детальном режиме отчётов:

- «Ведомость снятия показаний»;
- «Оборотно-сальдовая ведомость»;
- «Список не снятых показаний»;
- «Новые лицевые счета»;
- «Отчёт по оплатам»;
- «Отчёт по неоплаченным»;
- «Замена/установка счётчика»;
- «Отчёт по долгам»;
- «Отчёт по потреблениям».

«Процент снятия по контроллерам» этих фильтров не имеет: его строки — сами контроллеры, а не абоненты.

Фильтры по адресу и контроллерам действуют только в детальном режиме. Сводный режим («По городам», «По районам», «По улицам», «По контроллерам») их не учитывает — ни на экране, ни в XLSX-выгрузке, так же как фильтры по датам.

Это правило относится к готовым отчётам. В конструкторе отчётов фильтры сознательно действуют и в сводном режиме — см. «Конструктор отчётов».

Фильтры отбирают строки по адресу и зоне абонента строки: у счётчика, показания, оплаты и квитанции — по их абоненту, у отчётов, где строка — сам абонент, — по самому абоненту. Остальные фильтры отчёта, в том числе фильтры по датам, остаются и работают вместе с фильтрами по адресу и контроллерам.

Все перечисленные отчёты реализуют контракт `App\Reports\Contracts\FiltersExcelExport`: XLSX-выгрузка детального режима повторяет все применённые фильтры отчёта — по адресу, по контроллерам и по датам. Экранная таблица и выгрузка используют одно определение фильтров, поэтому выгружается тот же набор строк, что виден на экране. Отложенные значения фильтра, которые ещё не применены кнопкой, в выгрузку не попадают, поиск по таблице на выгрузку не влияет. Порядок строк и колонки выгрузки от фильтров не меняются.

Фильтр по контроллерам работает и когда строка отчёта — сам абонент: в этом случае зона ответственности применяется к запросу абонентов напрямую, без перехода по связи.

Зоны всех выбранных контроллеров читаются вместе, постоянным числом запросов независимо от количества выбранных контроллеров, и применяются одним условием: абонент организации в любом из назначенных им районов или на любой из назначенных улиц. Контроллер без назначенных районов и улиц строк не добавляет; если ни у одного выбранного контроллера зоны нет, отчёт пуст.

## Ведомость снятия показаний

Ведомость снятия показаний в коде называется `MeterReadingSheetReport`.

Отчёт показывает активные счётчики активных абонентов выбранной tenant-организации.

Для контроллера отчёт показывает только активные счётчики активных абонентов из назначенных регионов и улиц.

Строки сортируются по лицевому счёту абонента и номеру счётчика.

Если у одного абонента несколько счётчиков, они отображаются соседними строками.

Колонки отчёта:

- лицевой счёт;
- ФИО / наименование абонента;
- адрес;
- количество проживающих;
- счётчик;
- дата установки счётчика;
- предыдущее показание;
- текущее показание.

«Предыдущее показание» — показание на начало текущего расчётного месяца (открытого или ошибочного, как в остальных отчётах): последнее снятое показание счётчика (`current_reading` заполнено) за расчётный месяц раньше текущего. Если таких показаний нет, предыдущее показание равно начальному показанию счётчика. Показание текущего месяца в эту колонку не попадает никогда — правило то же, что у колонки «Предыдущее» в массовом вводе показаний.

«Текущее показание» — снятое показание счётчика за текущий расчётный месяц. Пока показание не снято, ячейка пустая: в неё контроллер пишет показание от руки на распечатке.

Отметка о визите без показания (`current_reading = null`) не считается ни предыдущим, ни текущим показанием.

Если открытого или ошибочного расчётного месяца нет, «Предыдущее показание» — последнее снятое показание счётчика за любой месяц (без показаний — начальное), «Текущее показание» пустое.

Показания выводятся целыми числами. Оба значения считаются подзапросами в запросе отчёта, без отдельного запроса на каждую строку.

Отчёт фильтруется по городу, району и улицам абонента, по контроллерам и по дате установки счётчика.

Ведомость можно скачать со страницы отчёта в формате XLSX.

XLSX-выгрузка использует тот же tenant-scope, тот же порядок строк и те же колонки со значениями, что и экранный отчёт: «Предыдущее показание» и «Текущее показание» выгружаются целыми числами, не снятое текущее показание — пустой ячейкой.

Для контроллера XLSX-выгрузка использует тот же фильтр зоны ответственности, что и экранная таблица.

XLSX-выгрузка ведомости повторяет фильтры, применённые на странице отчёта: выгружается тот же набор строк, что виден в детальном режиме с теми же фильтрами. Экранная таблица и выгрузка используют одно определение фильтров и применяют их одинаково, поэтому правила совпадают. Отложенные значения фильтра, которые оператор ещё не применил кнопкой, в выгрузку не попадают. Поиск по таблице на выгрузку по-прежнему не влияет, поэтому при активном поиске в выгрузке будет больше строк, чем на экране.

Отчёт реализует контракт `App\Reports\Contracts\FiltersExcelExport`, как и остальные отчёты с фильтрами по адресу и контроллерам. «Процент снятия по контроллерам» этот контракт не реализует и выгружает полный список.

## Список не снятых показаний

Список не снятых показаний в коде называется `MissingMeterReadingsReport`.

Отчёт показывает активные счётчики активных абонентов выбранной tenant-организации с типом начисления `meter`, по которым нет показания за текущий открытый или ошибочный расчётный месяц.

Если текущий расчётный месяц не открыт, отчёт не показывает строки и сообщает, что месяц нужно открыть.

Для контроллера отчёт показывает только активные счётчики активных абонентов из назначенных регионов и улиц.

Строки сортируются по лицевому счёту абонента и номеру счётчика.

Колонки отчёта:

- лицевой счёт;
- ФИО / наименование абонента;
- адрес;
- количество проживающих;
- счётчик;
- дата установки счётчика;
- текущий расчётный период;
- предыдущее показание.

Предыдущее показание берётся из последнего сохранённого текущего показания счётчика до текущего расчётного месяца.

Если по счётчику ещё нет сохранённых показаний, предыдущее показание равно начальному показанию счётчика.

Список можно скачать со страницы отчёта в формате XLSX.

XLSX-выгрузка использует тот же tenant-scope, тот же период, тот же порядок строк и те же колонки, что и экранный отчёт.

В детальном режиме отчёт фильтруется по городу, району и улицам абонента, по контроллерам и по дате установки счётчика. XLSX-выгрузка детального режима повторяет применённые фильтры.

## Отчёт по оплатам

Отчёт по оплатам в коде называется `PaymentsReport`.

Отчёт показывает оплаты выбранной tenant-организации за текущий открытый или ошибочный расчётный месяц.

Если текущий расчётный месяц не открыт, отчёт не показывает строки и сообщает, что месяц нужно открыть.

Для контроллера отчёт показывает только оплаты абонентов из назначенных регионов и улиц.

Строки сортируются по дате оплаты и идентификатору оплаты.

Колонки отчёта:

- лицевой счёт;
- абонент;
- адрес;
- текущий расчётный период;
- дата оплаты;
- сумма оплаты;
- способ оплаты;
- примечание.

Отчёт можно скачать со страницы отчёта в формате XLSX.

XLSX-выгрузка использует тот же tenant-scope, тот же период, тот же порядок строк и те же колонки, что и экранный отчёт.

В детальном режиме отчёт фильтруется по городу, району и улицам абонента, по контроллерам и по дате оплаты. XLSX-выгрузка детального режима повторяет применённые фильтры.

## Отчёт по неоплаченным

Отчёт по неоплаченным в коде называется `UnpaidReceiptsReport`.

Отчёт показывает квитанции текущего открытого или ошибочного расчётного месяца, где `amount > paid_amount`.

## Оборотно-сальдовая ведомость

Оборотно-сальдовая ведомость в коде называется `TurnoverBalanceSheetReport`.

Отчёт показывает сальдо на начало периода, обороты за период и сальдо на конец периода по лицевым счетам выбранного расчётного месяца.

Строка отчёта — один абонент. Строки сортируются по лицевому счёту и идентификатору абонента.

Для контроллера отчёт показывает только абонентов из назначенных регионов и улиц.

### Расчётный месяц

Отчёт реализует контракт `App\Reports\Contracts\SelectsBillingPeriod` и строится за выбранный расчётный месяц.

По умолчанию выбирается последний закрытый расчётный месяц, иначе текущий открытый или ошибочный, иначе последний расчётный месяц организации.

### Источник данных

Закрытый расчётный месяц зафиксирован, поэтому значения берутся из начисления `Accrual` за этот месяц. В отчёт попадают только абоненты, у которых есть начисление за выбранный месяц.

Открытый, ошибочный или считающийся расчётный месяц ещё собирается, поэтому в отчёт попадают все активные абоненты организации, а значения считаются по первичным данным:

- начальное сальдо — конечное сальдо начисления за последний предыдущий расчётный месяц плюс входящие остатки (корректировки типа `opening_balance`) за выбранный месяц;
- начислено — сумма квитанции `Receipt` за выбранный месяц, иначе `0`;
- оплачено — сумма оплат `Payment` за выбранный месяц;
- корректировка — сумма корректировок сальдо `BalanceAdjustment` за выбранный месяц без входящих остатков.

Квитанция создаётся при сохранении показания счётчика, поэтому в незакрытом месяце у абонентов с типом начисления `fixed` и `per_person` начислено равно `0` до закрытия месяца.

Конечное сальдо в ведомости всегда пересчитывается по формуле `Начальное сальдо + Начислено − Оплачено + Корректировка`, поэтому ведомость сходится независимо от сохранённого `closing_balance`.

Входящий остаток показывается в начальном сальдо периода, в котором он введён, — в том числе в открытом первом месяце организации — и не попадает в колонку «Корректировка» и обороты. В закрытом месяце он уже входит в сохранённое `opening_balance` начисления.

### Дебет и кредит

Дебет — долг абонента, кредит — переплата.

- Сальдо на начало Дебет — положительное начальное сальдо, Кредит — модуль отрицательного начального сальдо;
- Оборот Дебет — начислено плюс положительная корректировка;
- Оборот Кредит — оплачено плюс модуль отрицательной корректировки;
- Сальдо на конец Дебет — положительное конечное сальдо, Кредит — модуль отрицательного конечного сальдо.

Разложение считается по каждому абоненту и только потом суммируется, поэтому в сводке видны и общий долг, и общая переплата группы.

В каждой строке и в строке «Итого» выполняется тождество:

`Сальдо нач. Дебет − Сальдо нач. Кредит + Оборот Дебет − Оборот Кредит = Сальдо кон. Дебет − Сальдо кон. Кредит`

### Колонки

Колонки отчёта:

- лицевой счёт;
- абонент;
- адрес;
- расчётный период;
- объём;
- сальдо на начало периода — дебет;
- сальдо на начало периода — кредит;
- оборот — дебет;
- оборот — кредит;
- сальдо на конец периода — дебет;
- сальдо на конец периода — кредит;
- начислено;
- корректировка;
- оплачено.

Начислено, корректировка и оплачено расшифровывают обороты. Они показаны по умолчанию и скрываются переключателем колонок.

Колонка объёма подписывается единицей измерения услуги организации, например «Объём, м3». Если у организации нет услуги, колонка называется «Объём».

Объём — это расход по счётчикам за период, поэтому колонка заполнена только у абонентов с расчётом по счётчику. За закрытый расчётный месяц объём берётся из начисления, за незакрытый — из квитанции периода.

У абонентов с фиксированной суммой и с расчётом на одного человека колонка пустая. В начислении на одного человека поле объёма хранит количество проживающих, а не расход, поэтому ведомость его не показывает: иначе итог складывал бы кубометры с людьми.

В итогах и сводках пустой объём считается нулём.

Под колонкой объёма и денежными колонками детального режима выводятся итоги по всем строкам отчёта с учётом применённых фильтров.

## Конструктор отчётов

Конструктор собирает разовый отчёт на странице из разрешённого набора полей. Отчёт не пишется в коде и не сохраняется.

Страница в коде называется `App\Filament\Pages\Reports\BuildReport`, адрес — `reports/custom`, заголовок — «Конструктор отчётов». Пункт навигации стоит в группе «Учёт» сразу после «Отчёты», а на странице «Отчёты» над списком есть карточка-ссылка на конструктор.

### Доступ

Конструктор открывает только оператор организации (`OrganizationMemberAccess::canManageTenant()`), как страницу «Приём оплат». Контроллер не видит ни пункт навигации, ни карточку на странице «Отчёты», а прямой адрес отвечает ему 403.

### Сборка в адресе, без шаблонов

Шаблоны не сохраняются: нет ни таблиц, ни моделей, ни миграций для сборок. Вся сборка живёт в адресе страницы, поэтому ссылку можно переслать:

- `source` — источник данных;
- `fields` — выбранные поля через запятую;
- `group` — измерение сводки, `none` — «Без группировки»;
- `off` — выключенные показатели через запятую;
- `period` — расчётный месяц;
- `mode` — `detail` или `summary`.

Значение по умолчанию в адрес не пишется. Фильтры таблицы в адрес не входят и сбрасываются при открытии ссылки.

Кнопка «Сбросить» открывает страницу заново со значениями по умолчанию: источник «Оплаты», его колонки, группировка по улицам, все показатели, режим «Детально», расчётный месяц по умолчанию и пустые фильтры.

### Границы безопасности

Адрес и состояние Livewire — пользовательский ввод, поэтому:

- никакой SQL, имена таблиц или столбцов из запроса не принимаются: каждое значение `source`, `fields`, `group` и `off` ищется по ключу в каталоге источника, а неизвестное молча игнорируется, и подставляется значение по умолчанию источника (без единого известного поля — колонки источника по умолчанию);
- выражения полей, измерений и показателей заданы только в коде каталога;
- тенант и ограничение по роли применяются к базовому запросу источника до любых выбранных фильтров; фильтры добавляются поверх и умеют только сужать выборку;
- идентификаторы в фильтрах — только положительные целые, принадлежащие текущей организации (правила `ClientAddressFilter` и `ControllerZoneFilter`); собственные фильтры источника принимают только известные значения способа оплаты, типа абонента, статуса счётчика и статуса абонента, а неизвестное значение фильтр не применяет;
- `period` принимается, только если это положительное целое число, записанное цифрами, и расчётный месяц текущей организации; дробь (`12.9`, `12.0`), экспонента (`12e0`), знак, пробелы и чужой месяц дают месяц по умолчанию источника. Проверяется исходное значение адреса, а не то, во что его превратил разбор JSON Livewire.

### Каталог источников

Каталог живёт в `app/Reports/Builder`:

- `ReportSource` — контракт источника: ключ, подпись, подсказка, базовый запрос (тенант и ограничение по роли), поля, измерения, показатели, колонки строки сводки, фильтры, расчётный месяц по умолчанию. Показатели источник перечисляет сам: счётчик строк (`ReportMetric::count`) не обязателен, и у источника, где строка — сам абонент, его нет;
- `ReportSourceRegistry` — реестр источников, первый источник — источник по умолчанию;
- `ReportField` — поле: ключ, подпись, тип (`text`, `date`, `int`, `money`, `percent`, `float`), колонка или SQL-выражение, можно ли сортировать, вычисляемое ли оно;
- `ReportDimension` и `ReportMetric` — измерения и показатели сводки; сумма и среднее по умолчанию денежные, но источник задаёт им тип — у «Показаний счётчиков» сумма потребления целая, а среднее — дробное;
- `ReportBuild` — разбор адреса в сборку по каталогу;
- `BuiltReport` — экранная таблица обоих режимов и XLSX-выгрузка;
- `ReportSummaryQuery` — сводка одним запросом.

Источников четыре, в порядке на странице: «Оплаты», «Начисления», «Показания счётчиков», «Абоненты».

Колонка «Расчётный месяц» («Оплаты», «Начисления») показывает выбранный месяц отчёта. «Адрес» собирается так же, как в остальных отчётах: район, улица, дом, квартира.

Колонка «Контроллер» («Показания счётчиков», «Абоненты») — контроллеры, в зону которых попадает абонент строки, по тому же правилу, что колонка «Контроллеры» в разделе «Абоненты» (`App\Support\ClientControllers`): район или улица абонента назначены контроллеру текущей организации, имена через запятую по алфавиту, каждый один раз. Абонент вне зон — прочерк «—». Это то же правило, по которому строка попадает в группу сводки «По контроллерам» и проходит фильтр по контроллерам.

#### Оплаты

Строка — одна оплата абонента за выбранный расчётный месяц.

Поля: «Лицевой счёт», «Абонент», «Адрес», «Расчётный месяц», «Дата оплаты», «Способ оплаты», «Сумма», «Принял» (пользователь, принявший оплату в кассе; у оплаты провайдера пусто). По умолчанию выбраны все, кроме «Расчётный месяц» и «Принял».

Измерения: по городам, районам, улицам, контроллерам и по способам оплаты.

Показатели: «Абонентов», «Оплат», «Сумма оплат», «Средняя оплата».

Фильтр по дате — дата оплаты, собственный фильтр — способ оплаты.

Расчётный месяц по умолчанию — текущий открытый или ошибочный, иначе последний месяц организации.

#### Начисления

Строка — начисление абонента за выбранный расчётный месяц.

Строки и суммы берутся тем же движком, что оборотно-сальдовая ведомость (`App\Reports\TurnoverBalanceValues`), поэтому цифры конструктора совпадают с ней: в закрытом месяце — сохранённые начисления, в незакрытом — все активные абоненты с суммами по квитанциям, оплатам и корректировкам месяца (см. «Оборотно-сальдовая ведомость», «Источник данных»).

Поля: «Лицевой счёт», «Абонент», «Адрес», «Расчётный месяц», «Сальдо на начало», «Начислено», «Оплачено», «Долг на конец» и вычисляемые «Собираемость, %» и «Прирост долга». По умолчанию выбраны все, кроме «Расчётный месяц» и вычисляемых.

«Сальдо на начало» включает входящие остатки месяца, «Долг на конец» — конечное сальдо `Сальдо на начало + Начислено − Оплачено + Корректировка`: положительное — долг, отрицательное — переплата.

Измерения: по городам, районам, улицам, контроллерам и по типам абонентов.

Показатели: «Абонентов», «Начислений», «Начислено», «Среднее начисление», «Собираемость, %».

Фильтр по дате — дата начисления: в закрытом месяце — дата закрытия начисления, в незакрытом — дата формирования квитанции месяца (у абонента без квитанции даты нет, и при активном фильтре его строка скрывается). Собственный фильтр — тип абонента.

Расчётный месяц по умолчанию — тот же, что у оборотно-сальдовой ведомости: последний закрытый, иначе текущий открытый или ошибочный, иначе последний месяц организации.

#### Показания счётчиков

Строка — показание по счётчику за выбранный расчётный месяц.

Строки те же, что у «Отчёта по потреблениям»: показания, привязанные к выбранному месяцу (`meter_readings.billing_period_id`), у которых текущее показание заполнено. Отметка о визите без показания (`current_reading` пусто) — не показание: в строки, суммы и количество показаний она не попадает (см. «Счётчики»). Показания снятых (архивных) счётчиков остаются строками — их отбирает собственный фильтр.

Поля: «Лицевой счёт», «Абонент», «Адрес», «Счётчик» (номер), «Дата снятия», «Предыдущее», «Текущее», «Потребление», «Контроллер» и вычисляемое «Среднесуточное, м³». По умолчанию выбраны «Лицевой счёт», «Абонент», «Адрес», «Счётчик», «Дата снятия», «Текущее», «Потребление».

«Предыдущее», «Текущее» и «Потребление» — сохранённые значения показания (`previous_reading`, `current_reading`, `consumption`), те же, что в «Отчёте по потреблениям» и в начислении. Предыдущее показание заполняется системой при сохранении (у первого показания — начальное показание счётчика) и в базе пустым не бывает. «Дата снятия» у показания, принятого на странице ошибок закрытия без даты, пустая — прочерк «—».

Показания и потребление — целые числа на экране и в XLSX, включая показатель сводки «Потребление».

Измерения: по городам, районам, улицам и контроллерам. Собственного измерения у источника нет.

Показатели: «Абонентов», «Показаний», «Потребление» (сумма потребления группы, целое), «Среднее потребление» (потребление группы ÷ число её показаний, дробное).

Фильтр по дате — дата снятия показания (`meter_readings.read_at`); строка без даты при активном фильтре скрывается. Собственный фильтр — «Статус счётчика»: «Все счётчики» (без фильтра), «Активные», «Снятые» (счётчик отправлен в архив).

Расчётный месяц по умолчанию — текущий открытый или ошибочный, как у «Отчёта по потреблениям», иначе последний месяц организации.

Сумма «Потребление» в «Итого» совпадает с потреблением «Отчёта по потреблениям» за тот же месяц.

#### Абоненты

Строка — абонент организации: все абоненты, активные и неактивные, независимо от расчётного месяца. Статус отбирает собственный фильтр.

Поля: «Лицевой счёт», «Абонент», «Адрес», «Тип абонента», «Статус», «Услуги» (услуга организации абонента), «Проживающих», «Контроллер», «Долг» и вычисляемое «Долг на проживающего». По умолчанию выбраны «Лицевой счёт», «Абонент», «Адрес», «Тип абонента», «Проживающих», «Долг».

«Долг» — долг абонента на конец выбранного расчётного месяца. Он считается тем же движком, что оборотно-сальдовая ведомость, «Отчёт по долгам», касса и дашборд (`App\Reports\TurnoverBalanceValues`), поэтому цифры не расходятся:

- в незакрытом месяце (открытом, ошибочном, считающемся) — на сегодня: конечное сальдо прошлого начисления + входящие остатки месяца + квитанция месяца − оплаты месяца ± корректировки месяца. Так же, как на кассе, это считается и для неактивного абонента: его долг прошлых периодов остаётся долгом;
- в закрытом месяце — из начисления абонента за этот месяц. Если начисления за месяц нет (абонент был неактивен при закрытии или создан позже), сальдо в этом месяце у него нет, и «Долг» — прочерк «—», а не ноль.

Долг — положительная часть конечного сальдо, как «Долг» на кассе и в плитке дашборда «Долг абонентов»: переплата долгом не считается, у абонента с переплатой долг `0`. Поэтому сумма «Долг» активных абонентов в незакрытом месяце равна итогу «Отчёта по долгам» и плитке «Долг абонентов», а сумма «Долг» в закрытом месяце — «Сальдо кон. Дебет» ведомости за этот месяц.

Измерения: по городам, районам, улицам, контроллерам, по типам абонентов и по статусам.

Показатели: «Абонентов», «Долг» (сумма долга группы), «Средний долг» (долг группы ÷ число её абонентов; прочерк, если ни у одного абонента группы нет сальдо в месяце). Отдельного счётчика строк нет: строка — абонент, и число строк совпадает с «Абонентов», как и в остальных отчётах, где колонки «Строк» нет.

Фильтр по дате — дата создания абонента (`clients.created_at`). Собственный фильтр — «Статус абонента»: «Все статусы» (без фильтра), «Активный», «Неактивный».

Расчётный месяц по умолчанию — текущий открытый или ошибочный, то есть долг на сегодня, как на кассе и в «Отчёте по долгам», иначе последний месяц организации.

### Колонки

Колонки — галочки полей выбранного источника со счётчиком «выбрано N из M». Порядок колонок в таблице и в XLSX — порядок каталога, а не порядок кликов. Последнюю выбранную колонку убрать нельзя.

Колонки с SQL-значением сортируются, «Лицевой счёт», «Абонент» и «Счётчик» участвуют в поиске. «Адрес», «Расчётный месяц» и «Контроллер» не сортируются.

Переключение источника сбрасывает колонки, измерение и показатели на значения по умолчанию нового источника. Режим, расчётный месяц и общие фильтры (адрес, контроллеры) сохраняются; фильтр по дате и собственный фильтр у каждого источника свои.

### Вычисляемые колонки

Вычисляемые колонки — фиксированный набор, заданный в коде. Оператор не вводит формулы, он только выбирает, показывать ли колонку. В списке колонок такие поля помечены ярлыком «вычисляемое».

- «Собираемость, %» = `Оплачено ÷ Начислено × 100` («Начисления»);
- «Прирост долга» = `Долг на конец − Сальдо на начало` («Начисления»);
- «Среднесуточное, м³» = `Потребление ÷ число дней расчётного месяца` («Показания счётчиков»), дробное с двумя знаками; число дней берётся из месяца, к которому привязано показание, например 30 для июня;
- «Долг на проживающего» = `Долг ÷ Проживающих` («Абоненты»).

Формула считается в SQL, а не в PHP по строкам, поэтому колонка полноценная: сортируется и попадает в XLSX.

Деление на ноль и пустое значение в формуле дают прочерк «—», а не ошибку и не ноль: у абонента с нулевым начислением собираемость не определена, у абонента без проживающих (юрлица) — долг на проживающего, у абонента без сальдо в закрытом месяце — тоже.

### Режимы

«Детально» — таблица выбранных колонок с пагинацией по 50 строк, сортировкой и поиском, как в остальных отчётах.

«Сводно» — строки, сгруппированные по выбранному измерению, с выбранными показателями и последней строкой «Итого». Если измерение — «Без группировки», в сводном режиме страница просит выбрать измерение и показывает детальную таблицу; выбор «Без группировки» переключает режим на «Детально».

Сводка считается одним SQL-запросом независимо от числа групп: группы — `GROUP BY` по строкам отчёта, «Итого» — те же строки без группировки, присоединённые через `UNION ALL`. Перебора строк в PHP нет.

Показатели сводки:

- «Абонентов» — число уникальных абонентов группы; в «Итого» — число уникальных абонентов всего отчёта;
- «Оплат» / «Начислений» / «Показаний» — число строк группы; у «Абонентов» такого показателя нет — число строк равно «Абонентов»;
- «Сумма оплат» / «Начислено» / «Потребление» / «Долг» — сумма группы; «Потребление» — целое число;
- «Средняя оплата» / «Среднее начисление» / «Среднее потребление» / «Средний долг» — сумма группы, делённая на число её строк (у «Абонентов» строка — абонент, поэтому это долг на одного абонента группы);
- «Собираемость, %» — сумма оплаченного группы, делённая на сумму начисленного группы, × 100; при нулевом начисленном — «—».

Суммы и количества строк в «Итого» складываются из групп. Средние и проценты не суммируются и не усредняются по группам, а пересчитываются от итогов своей строки: собираемость района — оплаты района ÷ начисления района, собираемость «Итого» — все оплаты ÷ все начисления. Это то же правило, что у «Процента снятия» в готовых отчётах.

В сводке по контроллерам строка попадает к каждому контроллеру, чья зона подходит абоненту, как в готовых отчётах. Поэтому суммы «Итого» повторяют сумму видимых групп, а «Абонентов» в «Итого» считает каждого абонента один раз. Строки абонентов вне зон контроллеров в эту сводку не попадают.

Галочки «Показатели в сводке» выключают показатели: выключенный показатель пропадает из сводки на экране и из XLSX. Выключить можно и все показатели — тогда сводка показывает только группы и строку «Итого»; запрос сводки и в этом случае агрегирует строки и возвращает одну строку «Итого», а не строку на каждую запись источника.

### Фильтры

Фильтры — те же общие классы, что в остальных отчётах: `ClientAddressFilter` (город → район → улицы), `ControllerZoneFilter`, `DateRangeFilter` по дате источника и собственный фильтр источника. Выбор расчётного месяца — отдельное поле со всеми месяцами организации и их статусами, как у отчёта с `SelectsBillingPeriod`.

**Фильтры действуют в обоих режимах, включая сводный.** Это сознательное отличие от готовых отчётов, где сводка фильтры игнорирует (см. «Фильтры по адресу и контроллерам»): сводка конструктора строится из тех же отфильтрованных строк, что и детальная таблица.

Зоны выбранных контроллеров читаются постоянным числом запросов, как в остальных отчётах.

### Производительность

Детальный режим не делает запросов на строку: значения полей выбираются SQL-выражениями базового запроса, а связи, нужные выбранным колонкам (район и улица для «Адреса», абонент показания для «Контроллера»), загружаются для всей страницы заранее. Зоны контроллеров для колонки «Контроллер» читаются один раз на страницу или выгрузку (по запросу на районы и на улицы), сколько бы ни было строк.

### XLSX-выгрузка

Кнопка «Скачать XLSX» выгружает то, что на экране:

- в детальном режиме — выбранные колонки в порядке каталога и все строки с применёнными фильтрами, в порядке сортировки экрана (без сортировки — в порядке источника);
- в сводном режиме — сводку с выбранными показателями, строкой «Итого» и теми же фильтрами.

Поиск по таблице в выгрузку не попадает, как и в остальных отчётах. Отложенные значения фильтров, ещё не применённые кнопкой, тоже не попадают.

Выгрузка потоковая (`App\Reports\Contracts\FiltersExcelExport`, как у «Отчёта по оплатам»). Значения выгружаются так, как на экране: количества, показания и потребление — целыми числами, суммы — числами, округлёнными до копеек, дробные значения и проценты — числами с двумя знаками, даты — в виде `дд.мм.гггг`, пустые значения и деление на ноль — прочерком «—».
