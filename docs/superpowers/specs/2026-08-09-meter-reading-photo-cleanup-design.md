# Дизайн: очистка фото показаний при каскадном удалении

Дата: 2026-08-09

## Цель

Закрыть две отложенные находки финального ревью фичи «фото счётчика при вводе показания»:

1. При удалении счётчика или организации показания удаляются каскадом на уровне БД,
   минуя события модели `MeterReading`, — файлы фото остаются на диске навсегда.
2. Участник организации может подставить в `photo_path` путь фото другого показания
   своей же организации: два показания станут ссылаться на один файл, и удаление
   одного удалит фото у другого.

## Текущее состояние

- Фото показания хранится в `meter_readings.photo_path`, файлы — на диске `public`
  в каталоге `meter-reading-photos/{organization_id}/`.
- Очистка файла реализована хуками `updated` и `deleted` модели `MeterReading`.
- `meter_readings.meter_id` и `meter_readings.organization_id` объявлены
  `cascadeOnDelete()`, поэтому удаление счётчика или организации удаляет показания
  силами БД, без событий Eloquent.
- Из панели удалить можно только счётчик (действие в карточке счётчика, действие и
  массовое действие в карточке абонента). Организация удаляется лишь из кода или
  консоли; её удаление каскадом сносит и счётчики, поэтому хук на счётчике этот
  случай не покрывает.
- Клиента со счётчиками удалить нельзя: `meters.client_id` — `restrictOnDelete()`.

## Решение

### Класс хранения фото

Создаётся `App\Support\MeterReadingPhotoStorage` — единственное место, знающее про
диск и каталог фото:

| Метод | Назначение |
|---|---|
| `disk(): string` | Имя диска (`public`) |
| `directoryFor(int\|string $organizationId): string` | `meter-reading-photos/{organizationId}` |
| `delete(?string $path): void` | Удаляет один файл, игнорирует пустой путь |
| `deleteMany(array $paths): void` | Удаляет пачку файлов одной операцией |
| `deleteOrganizationDirectory(int\|string $organizationId): void` | Удаляет каталог организации целиком |

Существующие `MeterReading::PHOTO_DISK` и `MeterReading::photoDirectoryFor()`
делегируют в этот класс, чтобы не ломать вызовы в форме и тестах.

### Очистка при удалении счётчика

- Хук `deleting` модели `Meter` собирает непустые `photo_path` показаний счётчика
  чанками (`chunkById`), чтобы не поднимать в память тысячи записей.
- Хук `deleted` модели `Meter` удаляет собранные файлы.

Файлы удаляются после успешного удаления записи: если удаление откатится, фото
останутся целы.

### Очистка при удалении организации

Хук `deleted` модели `Organization` удаляет каталог `meter-reading-photos/{id}`
целиком. Это одна операция независимо от числа показаний, и она заодно подбирает
файлы, осиротевшие по любым другим причинам.

### Ужесточение проверки пути

В `allowFilePathUsing` (`MeterReadingForm::photoUpload()`) к текущим условиям
добавляется четвёртое: показание с этим `photo_path` должно относиться к тому же
счётчику, что и редактируемая форма.

Счётчик определяется по контексту формы:

- `meter_id` из состояния формы — форма ресурса показаний;
- record формы: `MeterReading` → его `meter_id`, `Meter` → его идентификатор;
- ownerRecord relation-менеджера, если это `Meter`.

Если счётчик определить не удалось, путь отклоняется.

Если Filament не предоставляет нужный контекст внутри замыкания, реализация
сообщает об этом вместо ослабления проверки.

## Что не меняется

- Хуки `updated`/`deleted` модели `MeterReading` — поведение сохраняется, меняется
  только источник знания о диске и каталоге.
- Схема БД: каскады `cascadeOnDelete` остаются как есть.
- Права доступа, формы, таблицы, отчёты.
- Отдельная artisan-команда зачистки осиротевших файлов не создаётся: хуков на
  счётчике и организации достаточно для всех путей удаления, доступных в системе.

## Тестирование

Pest, `Storage::fake('public')`:

- удаление счётчика удаляет файлы фото всех его показаний;
- удаление счётчика без фото проходит без ошибок;
- удаление организации удаляет каталог фото целиком;
- подмена `photo_path` на фото показания другого счётчика той же организации
  отклоняется валидацией;
- легитимная повторная отправка пути фото того же счётчика принимается.

Прогон тестов через `make test`.
