# Дизайн: фото счётчика при вводе показания

Дата: 2026-08-09

## Цель

Дать возможность прикрепить фото табло счётчика к показанию. Основной сценарий — контролёр
в обходе открывает панель в браузере телефона и при вводе показания фотографирует счётчик
камерой (или выбирает фото из галереи). Оператор проверяет ввод по миниатюрам в таблицах
показаний.

## Решение

Одна необязательная колонка `photo_path` в `meter_readings`, стандартный компонент Filament
`FileUpload` на диске `public`. Без новых зависимостей: диск `public`, symlink
`public/storage` и docker-volume `./storage` уже настроены.

## Схема данных

### Таблица `meter_readings`

- Добавляется `photo_path` — `string`, nullable, после `note`.
- Хранится относительный путь файла на диске `public`
  (например `meter-reading-photos/{organization_id}/AbC123....jpg`).

## Хранение файлов

- Диск: `public` (`storage/app/public`), файлы доступны по `APP_URL/storage/...`.
- Каталог: `meter-reading-photos/{organization_id}/` — файлы группируются по организации.
- Имя файла — случайный хэш (стандартное поведение Filament FileUpload).
- Лимиты достаточны: PHP в docker — 32M (`docker/app/php.ini`), Livewire по умолчанию — 12M
  на файл. Конфигурация не меняется.

## Формы (панель Filament)

Поле «Фото счётчика» добавляется во все три точки ввода показаний:

1. `MeterReadingForm` (ресурс показаний, создание/редактирование);
2. модальная форма показаний в карточке счётчика (`ReadingsRelationManager`);
3. модалка «Добавить/Изменить показание» у счётчика в карточке абонента
   (`MetersRelationManager`, action `addReading`).

Чтобы не дублировать настройку в трёх местах, сборка поля выносится в общий метод
(по конвенции проекта — schema-класс `MeterReadingForm`, который переиспользуют
relation-менеджеры).

Параметры поля:

- `FileUpload::make('photo_path')` → `->image()` — на телефоне открывает выбор
  «камера / галерея»;
- диск `public`, каталог `meter-reading-photos/{organization_id}` текущей tenant-организации;
- клиентский ресайз до 1920px по длинной стороне — фото с телефона ужимается до сотен КБ
  ещё до загрузки;
- максимальный размер файла 10 МБ;
- необязательное для всех ролей;
- одно фото; при загрузке нового прежнее заменяется.

## Таблицы показаний

- В таблицу ресурса показаний (`MeterReadingsTable`) и в таблицу показаний карточки счётчика
  (`ReadingsRelationManager`) добавляется колонка-миниатюра фото; клик открывает фото в
  полный размер (в новой вкладке).
- У показаний без фото колонка пустая.

## Очистка файлов

В модели `MeterReading`:

- при обновлении с заменой или очисткой `photo_path` старый файл удаляется с диска;
- при удалении показания файл удаляется с диска.

## Права

Без изменений. Фото загружает и меняет тот, кто может создавать/изменять показание:
оператор — по всем счётчикам организации, контролёр — по счётчикам своей зоны.
Удалять показание (вместе с фото) может только оператор.

## Что не меняется

- Валидации показаний (период, уникальность, previous_reading) — без изменений.
- Формирование квитанций по показанию — без изменений.
- Отчёты и XLSX-выгрузки — фото не участвует.
- Печатные формы (квитанция, карточка абонента) — без изменений.

## Тестирование

Pest, `Storage::fake('public')`:

- сохранение показания с фото через форму — файл появляется на диске, путь в `photo_path`;
- замена фото — старый файл удаляется с диска;
- удаление показания — файл удаляется с диска;
- показание без фото сохраняется как раньше.

Прогон тестов через `make test`.
