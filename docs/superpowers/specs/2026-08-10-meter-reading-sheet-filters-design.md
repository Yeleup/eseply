# Фильтры по адресу и контроллерам в ведомости снятия показаний

Дата: 2026-08-10

## Задача

Отчёт «Ведомость снятия показаний» (`App\Reports\MeterReadingSheetReport`) выводит все активные счётчики активных абонентов организации. Ведомость печатают для обхода конкретного участка, поэтому в отчёт нужны фильтры по городу, району, улицам и контроллерам.

Сейчас у отчёта есть только фильтр диапазона дат установки счётчика (`App\Filament\Support\DateRangeFilter`).

## Решения

| Вопрос | Решение |
| --- | --- |
| Учитывает ли XLSX-выгрузка новые фильтры | Да, но только в этом отчёте. Остальные отчёты не меняются |
| Множественный выбор | Улицы и контроллеры — множественно, город и район — одиночно |
| Каскадность списков | Да: город сужает районы, район сужает улицы |
| Кому виден фильтр по контроллерам | Всем ролям |

## Фильтры детального режима

Новые классы в `app/Filament/Support/` рядом с существующим `DateRangeFilter`.

### `ClientAddressFilter`

Один `Filter::make('address')` с каскадной схемой из трёх полей — так же, как адрес заполняется в `App\Filament\Resources\Clients\Schemas\ClientForm`.

| Поле | Компонент | Опции |
| --- | --- | --- |
| `city_id` | `Select`, одиночный, `live()` | города tenant-организации по имени |
| `region_id` | `Select`, одиночный, `live()` | районы выбранного города; без выбранного города — все районы организации с подписью «Город / Район» |
| `street_ids` | `Select`, `multiple()` | улицы выбранного района; без района, но с городом — улицы города; иначе все улицы организации. Пока район не выбран, подпись имеет вид «Район / Улица» |

Правила поведения:

- смена города обнуляет район и улицы;
- смена района обнуляет улицы;
- каждое поле работает независимо: можно выбрать только улицы, не выбирая город и район;
- пустое поле фильтр не применяет.

Применение к запросу (в отчёте таблица `clients` уже присоединена):

- `city_id` → `whereIn('clients.region_id', <районы города>)`;
- `region_id` → `where('clients.region_id', <район>)`;
- `street_ids` → `whereIn('clients.street_id', <улицы>)`.

Индикаторы: отдельный индикатор на каждое заполненное поле, снимается по отдельности через `Indicator::removeField()` — как у `DateRangeFilter`.

### `ControllerZoneFilter`

`SelectFilter::make('controller_ids')->multiple()->searchable()`.

Опции — пользователи с ролью контроллера в текущей организации, подпись `«Имя (email)»`, как в `App\Filament\Resources\Receipts\Tables\ReceiptsTable::controllerOptions()`.

Применение к запросу: строка отчёта проходит, если абонент попадает в зону ответственности **хотя бы одного** выбранного контроллера. Зона переиспользуется из `Client::scopeVisibleToOrganizationMember($controller, $tenant)` — то есть совпадение по назначенному району или назначенной улице.

Значения, которые не являются контроллерами этой организации, отбрасываются. Если после отбрасывания не осталось ни одного контроллера, отчёт показывает пустой результат.

### Порядок фильтров в панели

1. Город / Район / Улицы.
2. Контроллеры.
3. Дата установки (существующий).

## XLSX-выгрузка

Новый контракт `App\Reports\Contracts\FiltersExcelExport`:

```php
interface FiltersExcelExport
{
    /**
     * @param  array<string, array<string, mixed>>  $filters
     */
    public function downloadFilteredExcel(Organization $organization, User $user, array $filters): StreamedResponse;
}
```

Контракт реализует только `MeterReadingSheetReport`. Его обычный `downloadExcel()` вызывает `downloadFilteredExcel()` с пустым массивом, поэтому поведение при вызове напрямую не меняется.

`App\Filament\Pages\Reports\ViewReport::downloadExcel()` в детальном режиме проверяет отчёт на `instanceof FiltersExcelExport` и передаёт применённое состояние фильтров `$this->tableFilters`. Свойство `tableFilters` содержит именно применённое состояние: отложенные значения Filament хранит отдельно, в `tableDeferredFilters`. Значения, не являющиеся массивом, отбрасываются на этой границе — дальше состояние фильтров считается доверенным по форме, но не по содержимому.

Отчёт применяет фильтры к запросу выгрузки так же, как Filament применяет их к экранной таблице: сначала `applyToBaseQuery()` каждого фильтра, затем все фильтры внутри одной вложенной группы `where()`. Список фильтров у таблицы и у выгрузки один и тот же.

Не меняется:

- сводный режим;
- остальные семь отчётов;
- имя файла выгрузки;
- набор и порядок колонок;
- то, что поиск по таблице в выгрузку не попадает.

## Доступ

Фильтры только сужают базовый запрос, который уже ограничен `visibleToOrganizationMember($user, $organization)`.

Списки опций Filament не являются границей доступа: состояние фильтра приходит из Livewire и может быть подменено. Подмена безопасна, потому что любой фильтр добавляет к запросу только дополнительные ограничения и не может расширить видимость. Контроллер, подставивший идентификатор чужого контроллера, увидит пересечение двух зон, то есть не больше собственной зоны.

## Тесты

`tests/Feature/OrganizationReportsTest.php`:

- фильтр по городу оставляет только абонентов районов этого города;
- фильтр по району оставляет только абонентов этого района;
- фильтр по нескольким улицам оставляет абонентов любой из выбранных улиц;
- фильтр по нескольким контроллерам оставляет абонентов из зоны любого из них, абонент из зоны обоих не дублируется;
- контроллер с идентификатором чужого контроллера в фильтре не видит чужих абонентов;
- каскад: список районов сужается выбранным городом, список улиц — выбранным районом;
- смена города очищает район и улицы, смена района очищает улицы;
- некорректные значения в состоянии фильтра игнорируются;
- XLSX-выгрузка учитывает применённые фильтры по адресу, по контроллерам и по дате установки;
- XLSX-выгрузка не учитывает отложенные значения фильтра, которые оператор ещё не применил;
- XLSX-выгрузка без фильтров возвращает полный список, как раньше.
