# Дашборд организации

Дата: 2026-08-10

## Задача

При входе в панель оператор попадает на список абонентов: корневой маршрут tenant-организации перенаправляет на `ClientResource` (`App\Providers\Filament\AdminPanelProvider`). Общей картины по организации в системе нет — чтобы понять состояние месяца, руководителю нужно открыть несколько отчётов подряд.

Нужен дашборд, который в одном окне показывает снятие показаний, начисления, оплаты, долг и количество абонентов за выбранный расчётный месяц.

## Решения

| Вопрос | Решение |
| --- | --- |
| Где живёт дашборд | Стартовая страница панели, путь `/` внутри tenant |
| Период | Селектор расчётного месяца, по умолчанию текущий редактируемый |
| Что видит контроллер | Только снятие показаний по своей зоне, без денег |
| Откуда берутся начисления | Закрытый месяц — `accruals`, открытый и ошибочный — `receipts` |
| Где живёт арифметика | Новый сервис `App\Dashboard\DashboardMetrics` |
| Кэш | Не используется |

## Размещение и маршрут

`App\Filament\Pages\Dashboard` наследует `Filament\Pages\Dashboard` и подхватывается существующим `discoverPages(in: app_path('Filament/Pages'))`.

Родительский класс объявляет `protected static string $routePath = '/'`, поэтому дашборд занимает корень tenant-области. Текущий редирект на список абонентов в `authenticatedTenantRoutes()` удаляется — иначе два маршрута претендуют на один путь. Имя маршрута `filament.admin.tenant.home` больше нигде в приложении не используется.

Заголовок страницы — «Дашборд», иконка `Heroicon::OutlinedHome`, `navigationSort` меньше, чем у остальных пунктов, чтобы дашборд стоял первым в меню.

Страница добавляется в `scopes` рендер-хука `PanelsRenderHook::PAGE_START`, поэтому существующая плашка `filament.billing-period-required-callout` показывает состояние «месяц не открыт» и «месяц закрывается» и на дашборде.

## Селектор расчётного месяца

Страница использует `Filament\Pages\Dashboard\Concerns\HasFiltersForm`. Форма фильтров содержит один `Select` с именем `billing_period_id`.

Опции — все расчётные месяцы организации, отсортированные по `starts_on` по убыванию, подпись — `label` модели (`08.2026`). Статус месяца выводится подсказкой рядом со значением: `open`, `processing`, `closed`, `failed`.

Значение по умолчанию выбирается так:

1. текущий редактируемый месяц — `BillingPeriod::currentEditableFor($organization)`;
2. если такого нет — последний месяц организации по `starts_on`;
3. если у организации нет ни одного месяца — селектор пуст.

Значение из состояния Livewire может быть подменено, поэтому страница разрешает только идентификатор месяца, принадлежащего текущей организации. Любое другое значение считается отсутствующим и приводит к выбору по умолчанию.

Виджеты получают выбранный месяц через `Filament\Widgets\Concerns\InteractsWithPageFilters` и сами приводят `$this->pageFilters['billing_period_id']` к модели тем же правилом.

## Источники цифр

`Accrual` создаётся только при закрытии месяца (`App\Actions\CloseBillingMonth`), а `Receipt` появляется по ходу открытого месяца при вводе показаний. Поэтому источник денег зависит от статуса месяца:

| Метрика | Месяц `closed` | Месяц `open`, `processing`, `failed` |
| --- | --- | --- |
| Начислено | `SUM(accruals.amount)` | `SUM(receipts.amount)` |
| Долг на конец месяца | `SUM(accruals.closing_balance)` при `closing_balance > 0` | `SUM(receipts.closing_balance)` при `closing_balance > 0` |
| Абонентов с долгом | `COUNT(accruals)` при `closing_balance > 0` | `COUNT(receipts)` при `closing_balance > 0` |
| Оплачено | `SUM(payments.amount)` за месяц | то же |
| Оплат | `COUNT(payments)` за месяц | то же |

Для незакрытого месяца начисление считается предварительным: квитанции есть только у абонентов, по которым уже сняли показание. Плитка «Начислено» в этом случае подписывается «предварительно, по N квитанциям».

Процент сбора — `оплачено / начислено`, при нулевом начислении равен нулю.

## Сервис `App\Dashboard\DashboardMetrics`

Новая папка `app/Dashboard` рядом с существующей `app/Reports`. Дашборд строит собственные агрегатные запросы, чтобы изменения в нём не задевали отчёты и их XLSX-выгрузки. Единственное исключение — подсчёт активных счётчиков в зоне контроллера: он вынесен в общий класс `App\Support\ControllerZoneMeterCounts`, которым пользуются и отчёт «Процент снятия по контроллерам», и дашборд, чтобы правило зоны не разъехалось между ними. Поведение отчёта при этом не меняется.

Сервис разделён на два метода по границе доступа, а не по блокам экрана: денежные цифры считаются отдельным методом, который вызывают только виджеты оператора.

```php
namespace App\Dashboard;

final class DashboardMetrics
{
    /**
     * @return array{
     *     clients_active:int, clients_total:int, clients_new:int,
     *     meters_active:int, meters_metered:int,
     *     readings_taken:int, readings_expected:int, readings_percent:float,
     *     consumption:int
     * }
     */
    public function operations(Organization $organization, BillingPeriod $billingPeriod, User $user): array;

    /**
     * @return array{
     *     charged:float, charged_is_preliminary:bool, charged_documents:int,
     *     paid:float, payments_count:int, collection_percent:float,
     *     debt:float, debtors_count:int
     * }
     */
    public function finance(Organization $organization, BillingPeriod $billingPeriod): array;

    /**
     * @return list<array{period:string, label:string, charged:float, paid:float}>
     */
    public function monthlyTotals(Organization $organization, int $months = 12): array;

    /**
     * @return list<array{
     *     controller_id:int, name:string, email:string,
     *     total:int, taken:int, missing:int, percent:float
     * }>
     */
    public function controllerProgress(Organization $organization, BillingPeriod $billingPeriod, User $user): array;

    /**
     * @return list<array{
     *     region_id:int, region:string, city:string, clients:int,
     *     readings_percent:float, charged:float, paid:float, debt:float
     * }>
     */
    public function regionBreakdown(Organization $organization, BillingPeriod $billingPeriod): array;
}
```

Правила расчёта:

- `clients_active` — `clients.status = 'active'`, `clients_total` — все абоненты организации;
- `clients_new` — `clients.created_at` в границах календарного месяца периода, как в `NewClientAccountsReport`: от начала дня `starts_on` до конца дня последнего дня месяца;
- `meters_active` — счётчики со статусом `active` у активных абонентов; `meters_metered` — из них у абонентов с `billing_type = 'meter'`;
- `readings_expected` — счётчики из `meters_metered`; `readings_taken` — те из них, по которым есть показание за выбранный месяц; `readings_percent` — отношение, при нулевом знаменателе равно нулю;
- `consumption` — `SUM(meter_readings.consumption)` за месяц, целое число;
- `monthlyTotals` — последние `months` расчётных месяцев организации по `starts_on`, для каждого начисление берётся по правилу из таблицы источников;
- `controllerProgress` — участники организации с ролью `controller`; знаменатель и числитель считаются так же, как в `ControllerMeterReadingProgressReport`: счётчик, попадающий к контроллеру одновременно по району и по улице, учитывается один раз; контроллер без назначенной зоны даёт нули;
- `regionBreakdown` — районы организации, у которых есть хотя бы один абонент; `clients` — активные абоненты района, `readings_percent` — доля снятых показаний по счётчикам района по тому же правилу, что и общий процент, `charged`, `paid` и `debt` — по правилу из таблицы источников; строки сортируются по долгу по убыванию, затем по названию района.

`operations()` и `controllerProgress()` принимают `User`, потому что ограничены зоной ответственности: базовые запросы строятся через существующие `Client::scopeVisibleToOrganizationMember()` и `Meter::scopeVisibleToOrganizationMember()`. Для контроллера `controllerProgress()` возвращает только его собственную строку.

`finance()` и `regionBreakdown()` `User` не принимают: они доступны только оператору, а оператор видит всю организацию.

Каждый показатель считается агрегатным запросом с `GROUP BY`, без загрузки моделей и без запроса в цикле. Модели читаются только там, где нужны подписи (контроллеры, районы).

## Виджеты

Все виджеты живут в `app/Filament/Widgets`, регистрируются страницей дашборда через `getWidgets()` и получают месяц из фильтров страницы. Сетка страницы — 4 колонки.

### Плитки

`StatsOverviewWidget` скрывается целиком, отдельную плитку скрыть нельзя, поэтому плитки разделены на два виджета по границе доступа.

`DashboardStatsWidget` — виден любому участнику организации, данные из `operations()`:

| Плитка | Значение | Описание |
| --- | --- | --- |
| Абоненты | активных | всего N · новых за месяц M |
| Счётчики | активных | по счётчику N |
| Снято показаний | процент | N из M |
| Потребление | сумма за месяц | единица измерения услуги организации (`utility_services.unit_of_measurement`) |

`DashboardFinanceStatsWidget` — виден только оператору, данные из `finance()`:

| Плитка | Значение | Описание |
| --- | --- | --- |
| Начислено | сумма | по N начислениям; для незакрытого месяца — «предварительно, по N квитанциям» |
| Оплачено | сумма | N оплат · сбор P % |
| Долг на конец месяца | сумма | N абонентов |

Оба виджета выводят плитки в 4 колонки. Цвет плитки «Снято показаний»: меньше 70 % — `danger`, меньше 95 % — `warning`, иначе `success`.

### `DashboardChargesChartWidget`

`ChartWidget` типа `bar`. Два набора данных — «Начислено» и «Оплачено» — за последние 12 расчётных месяцев организации, слева направо от старого к новому. Подписи оси — `MM.YYYY`. Виден только оператору. Занимает всю ширину страницы.

### `DashboardControllerProgressWidget`

`TableWidget` без пагинации.

Колонки: контроллер, всего счётчиков, снято, не снято, процент снятия. Процент окрашивается по тем же порогам, что и плитка. Сортировка по проценту по возрастанию — отстающие сверху.

Виден оператору и контроллеру. Контроллер видит одну строку — свою.

Показывается не больше 10 строк, под таблицей — ссылка на отчёт «Процент снятия по контроллерам».

### `DashboardRegionBreakdownWidget`

`TableWidget` без пагинации. Виден только оператору.

Колонки: район (с городом), абонентов, снято %, начислено, оплачено, долг.

Показывается не больше 10 строк с наибольшим долгом, под таблицей — ссылка на отчёт «Отчёт по долгам».

## Доступ

| Блок | Оператор | Контроллер |
| --- | --- | --- |
| Плитки «Абоненты», «Счётчики», «Снято показаний», «Потребление» | вся организация | своя зона |
| Плитки «Начислено», «Оплачено», «Долг» | да | скрыты |
| График начислений и оплат | да | скрыт |
| Прогресс снятия по контроллерам | все контроллеры | своя строка |
| Срез по районам | да | скрыт |

Правило «оплаты, начисления и квитанции доступны только оператору» из `docs/business-rules.md` сохраняется: денежные виджеты скрываются через `canView()`, а не вёрсткой, и денежные запросы для контроллера не выполняются вовсе.

Пользователь, не являющийся участником организации, не проходит tenant-проверку панели и до дашборда не доходит.

## Пустые состояния

- у организации нет ни одного расчётного месяца — вместо виджетов выводится плашка с предложением открыть месяц в разделе «Расчётные месяцы»;
- выбранный месяц есть, но данных нет — плитки показывают нули, таблицы показывают пустое состояние, график не рисует столбцы;
- у контроллера нет назначенной зоны — плитки показывают нули, строка прогресса показывает нули.

## Производительность

Виджеты Filament загружаются лениво, поэтому страница отдаётся сразу, а каждый блок считает свои агрегаты отдельным запросом. Все запросы ограничены `organization_id` и `billing_period_id` — по этим колонкам в учётных таблицах уже есть индексы.

Кэш не вводится: цифры дашборда должны совпадать с отчётами в тот же момент времени.

## Тесты

Тесты разделены на два файла: `tests/Feature/DashboardMetricsTest.php` проверяет сервис метрик, `tests/Feature/DashboardTest.php` — страницу, селектор месяца и виджеты.

- оператор открывает дашборд по корневому маршруту tenant-организации;
- плитки показывают количество активных абонентов, всего абонентов и новых за выбранный месяц;
- плитка снятия показаний считает только счётчики абонентов с типом начисления «по счётчику»;
- для закрытого месяца начисление и долг берутся из `accruals`;
- для открытого месяца начисление и долг берутся из `receipts` и помечаются как предварительные;
- оплачено и процент сбора считаются по оплатам выбранного месяца;
- переключение месяца в селекторе меняет цифры;
- подменённый идентификатор месяца из чужой организации не применяется — используется месяц по умолчанию;
- если открытого месяца нет, по умолчанию выбирается последний закрытый;
- контроллер видит дашборд, его плитки ограничены назначенными районами и улицами;
- контроллер не видит денежные плитки, график и срез по районам;
- контроллер без назначенной зоны видит нули;
- прогресс снятия для контроллера содержит только его строку, для оператора — всех контроллеров организации;
- срез по районам отсортирован по долгу по убыванию;
- организация без расчётных месяцев открывает дашборд без ошибок;
- данные другой организации в цифры не попадают.

Тесты запускаются командой `make test`.

## Что не входит

- фильтр по произвольному диапазону дат;
- фильтры по городу, району и контроллеру на самом дашборде;
- экспорт дашборда в XLSX;
- изменения в существующих отчётах и их выгрузках;
- изменения в расчёте начислений и закрытии месяца.
