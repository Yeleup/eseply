# Конструктор шаблона квитанции организации

Дата: 2026-08-11

## Задача

Квитанция печатается одним жёстким шаблоном `resources/views/receipts/partials/print-copy.blade.php` для всех организаций. Организации хотят собственный вид квитанции: свой состав и порядок блоков, свои тексты и подписи полей, логотип, QR-код для оплаты, настройки внешнего вида.

Нужен конструктор в браузере: администратор организации в панели Filament настраивает шаблон и сразу видит результат в живом предпросмотре. Печать (одиночная и массовая) использует настроенный шаблон; у организаций без настроек всё выглядит как сейчас.

## Решения

| Вопрос | Решение |
| --- | --- |
| Модель гибкости | Готовые блоки: включение/выключение, порядок, тексты, логотип/QR, внешний вид. Без свободного HTML |
| Кто настраивает | Администратор организации в своей панели (tenant-scoped) |
| Хранение | Таблица `receipt_templates`, одна запись на организацию, конфиг в JSON-колонке `settings` |
| Отсутствие записи | Печать использует дефолтный конфиг из кода — поведение не меняется |
| Предпросмотр | Livewire, рендер того же партиала `print-copy` на данных последней квитанции организации или на демо-данных |
| Безопасность | Пользовательского HTML нет; тексты выводятся экранированными, данные подставляются на сервере |

## Хранение

Миграция создаёт таблицу `receipt_templates`:

| Колонка | Тип | Назначение |
| --- | --- | --- |
| `id` | id | — |
| `organization_id` | foreignId, unique, cascadeOnDelete | Одна запись на организацию |
| `settings` | json | Конфиг шаблона |
| `logo_path` | string, nullable | Логотип организации (public-диск) |
| `qr_path` | string, nullable | QR-код для оплаты (public-диск) |
| timestamps | — | — |

Модель `App\Models\ReceiptTemplate` с `belongsTo(Organization::class)`, у `Organization` — `hasOne(ReceiptTemplate::class)`. Фабрика для тестов.

### Структура `settings`

```json
{
    "blocks": [
        {"type": "header", "enabled": true},
        {"type": "client_details", "enabled": true},
        {"type": "organization_details", "enabled": true},
        {"type": "meters_table", "enabled": true},
        {"type": "totals", "enabled": true},
        {"type": "footer_note", "enabled": false}
    ],
    "texts": {
        "title": "Квитанция на оплату коммунальной услуги",
        "footer_note": "",
        "labels": {}
    },
    "appearance": {
        "copies_per_page": 2,
        "font_size": "normal",
        "density": "normal",
        "borders": true,
        "show_logo": true,
        "show_qr": false
    }
}
```

Порядок элементов `blocks` определяет порядок блоков на квитанции. `texts.labels` — переопределения подписей полей по ключу (`account_number`, `client_name`, …); отсутствующий ключ означает стандартную подпись. `font_size` и `density`: `compact | normal | large`. `copies_per_page`: `1 | 2`.

### Дефолты и слияние

Класс `App\Support\ReceiptTemplateDefaults` отдаёт дефолтный конфиг (текущий вид квитанции: два экземпляра на листе, все блоки, кроме `footer_note`, включены, без логотипа и QR).

Класс `App\Support\ReceiptTemplateConfig` — итог слияния сохранённого `settings` с дефолтами:

- неизвестные ключи и типы блоков отбрасываются;
- отсутствующие ключи берутся из дефолтов;
- блоки, появившиеся в коде после сохранения шаблона, добавляются в конец списка выключенными (кроме случая, когда блок включён в дефолтах и запись о нём отсутствует, — тогда как в дефолтах);
- значения вне допустимых (`font_size: "huge"`) заменяются дефолтными.

Благодаря слиянию будущие возможности добавляются новыми ключами без миграций данных.

## Блоки квитанции

`print-copy.blade.php` разбивается на партиалы `resources/views/receipts/blocks/*.blade.php`. `print-copy` перебирает включённые блоки конфига по порядку и подключает соответствующий партиал.

| Тип блока | Партиал | Содержимое |
| --- | --- | --- |
| `header` | `header.blade.php` | Название организации, адрес, номер/период/дата; логотип при `show_logo` и загруженном файле |
| `client_details` | `client-details.blade.php` | Секция «Абонент» |
| `organization_details` | `organization-details.blade.php` | Секция «Реквизиты» |
| `meters_table` | `meters-table.blade.php` | Таблица счётчиков с итогами, долгом, оплатой и «К оплате» |
| `totals` | `totals.blade.php` | Итоговые строки «Долг», «Оплачено», «К оплате» — выделяются из таблицы счётчиков, чтобы блок работал и при выключенной таблице |
| `footer_note` | `footer-note.blade.php` | Произвольное примечание организации (`texts.footer_note`); QR-код при `show_qr` и загруженном файле |

В текущем шаблоне итоговые строки живут внутри таблицы счётчиков. При разбиении «Итого» (объём и сумма по счётчикам) остаётся в `meters_table`, а «Долг», «Оплачено», «К оплате» переходят в `totals` — так организация с фиксированным тарифом может выключить таблицу счётчиков, не теряя итогов.

`appearance` транслируется в CSS-классы обёртки `receipt-copy` (`receipt-density-compact`, `receipt-font-large`, `receipt-no-borders`). `copies_per_page` управляет циклом копий в `receipts/print.blade.php` и `receipts/bulk-print.blade.php`: при `1` печатается только экземпляр «Для абонента».

## Данные для печати

`App\Actions\BuildReceiptPrintViewData::handle()` дополнительно возвращает ключ `template` — `ReceiptTemplateConfig` организации квитанции (запись из БД, слитая с дефолтами, либо чистые дефолты). Туда же входят публичные URL логотипа и QR, если файлы загружены.

`ReceiptPrintController` не меняется: обе печати уже проходят через `BuildReceiptPrintViewData`, массовая печать получает шаблон автоматически.

Подписи полей в `clientDetails` и `organizationDetails` строятся с учётом `texts.labels`: экшен подставляет переопределённые подписи вместо стандартных.

## Страница-конструктор

`App\Filament\Pages\ReceiptTemplatePage` — полностраничная Livewire-страница панели `admin`, tenant-scoped, подхватывается `discoverPages`. Пункт навигации «Шаблон квитанции» в группе настроек. Доступ: `canManageOrganization` — как у печати квитанций; контроллерам страница не видна.

Макет — две колонки:

**Слева — форма настроек (Filament Schema):**

- сортируемый Repeater блоков: каждая строка — название блока и тумблер «Показывать», перетаскивание меняет порядок; добавление и удаление строк запрещено (`addable(false)`, `deletable(false)`), `header` выключить нельзя;
- секция «Тексты»: заголовок квитанции, примечание внизу, переопределения подписей полей;
- секция «Изображения»: `FileUpload` логотипа и QR (public-диск, каталог `receipt-templates/{organization_id}`, изображения до 1 МБ);
- секция «Внешний вид»: селекты размера шрифта и плотности, тумблер рамок, выбор 1/2 копий на листе, тумблеры «Показывать логотип» и «Показывать QR».

**Справа — живой предпросмотр:**

- рендер того же партиала `print-copy` внутри страницы с изолирующими стилями (масштаб под ширину колонки);
- данные — последняя квитанция организации (`Receipt::whereBelongsTo($tenant)->latest('id')`); если квитанций нет — демонстрационный `Receipt` в памяти (не сохраняется) с типовыми значениями;
- конфиг для предпросмотра собирается из текущего несохранённого состояния формы, поэтому изменения видны сразу (Livewire `live()`).

Кнопки: «Сохранить» (upsert записи `receipt_templates`) и «Сбросить к стандартному» (удаляет запись и файлы, форма возвращается к дефолтам, с подтверждением).

## Безопасность

- Свободный HTML недоступен: все настраиваемые тексты выводятся через экранирование Blade `{{ }}`.
- Файлы — только изображения, валидируются `FileUpload`, хранятся в каталоге организации.
- Страница и сохранение доступны только членам организации с правом управления; запись всегда ищется/создаётся по текущему tenant, идентификатор организации из формы не принимается.

## Тестирование

Pest feature-тесты:

1. Печать без записи шаблона рендерит все дефолтные блоки (текущее поведение).
2. Выключенный блок (`meters_table`) не попадает в HTML печати.
3. Порядок блоков в печати соответствует порядку в конфиге.
4. Переопределённый заголовок, подпись поля и примечание выводятся; HTML в тексте экранируется.
5. `copies_per_page = 1` печатает один экземпляр.
6. Слияние конфига: неизвестный блок отбрасывается, отсутствующий ключ берётся из дефолтов, новый блок из кода добавляется выключенным.
7. Страница конструктора: доступна админу организации, недоступна контроллеру; сохранение создаёт/обновляет запись текущего tenant; сброс удаляет запись.
8. Массовая печать применяет шаблон организации.

## Вне объёма

- Свободный drag&drop по холсту и пользовательский HTML/CSS.
- Несколько шаблонов на организацию, шаблоны на услугу.
- Генерация QR на лету (загружается готовое изображение; интеграция с Kaspi QR — отдельная задача).
- Настройка формата бумаги (остаётся текущий лист A5-компоновки).
