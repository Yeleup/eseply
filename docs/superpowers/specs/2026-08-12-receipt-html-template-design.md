# HTML-шаблон квитанции с переменными (v2)

Дата: 2026-08-12

## Задача

Блочный конструктор шаблона квитанции (v1, смержен в master) оказался слишком ограниченным: у части клиентов квитанции устроены совсем иначе, чем набор стандартных блоков. Нужен свободный HTML-шаблон с готовыми плейсхолдерами `{{переменная}}` и визуальным редактором с перетаскиванием элементов.

Решение согласовано с владельцем: **полная замена** блочного режима. Редактор — **GrapesJS** (npm, MIT), редактирует **администратор организации**, серверная санитизация HTML — **symfony/html-sanitizer** (composer). Обе новые зависимости одобрены.

## Решения

| Вопрос | Решение |
| --- | --- |
| Формат шаблона | HTML с плейсхолдерами `{{key}}` (латинские ключи из белого списка) + отдельный CSS от GrapesJS |
| Редактор | GrapesJS на странице «Шаблон квитанции»: холст, палитра готовых элементов, правка текста на месте |
| Кто редактирует | Админ организации (`canManageOrganization`), tenant-scoped |
| Блочный режим v1 | Удаляется полностью (`ReceiptTemplateConfig`, `ReceiptTemplateDefaults`, блоки-партиалы кроме таблицы счётчиков) |
| Без шаблона в БД | Печать рендерит дефолтный HTML-шаблон из файлов ресурсов — вид как у текущей квитанции |
| Существующие записи v1 | Блочные `settings` упраздняются; переносится только `copies_per_page`; логотип/QR-файлы сохраняются |
| Исполняемый код | Запрещён: никакого Blade/eval; свой рендерер подстановки по белому списку с экранированием |

## Хранение

Миграция изменяет `receipt_templates`:

- добавляет `html` (LONGTEXT, nullable), `css` (TEXT, nullable), `copies_per_page` (unsignedTinyInteger, default 2);
- переносит `settings->appearance->copies_per_page` существующих записей в новую колонку (значения кроме 1 и 2 → 2);
- удаляет колонку `settings`.

`logo_path`/`qr_path` не меняются. Запись по-прежнему одна на организацию. Модель: `#[Fillable([organization_id, html, css, copies_per_page, logo_path, qr_path])]`, событие `deleted` удаляет файлы (как в v1).

`html = null` означает «шаблон не настроен» — печать и стартовое содержимое редактора берут дефолт из файлов.

## Каталог переменных

Класс `App\Support\ReceiptTemplateVariables` — единственный источник правды: ключ → русское название (для палитры) → извлечение значения из `Receipt`.

**Скалярные** (значение экранируется при подстановке):

| Ключ | Название | Источник |
| --- | --- | --- |
| `organization_name` | Название организации | `organization.name` |
| `organization_address` | Адрес организации | `organization.address` |
| `organization_bin` | БИН / ИИН | `organization.bin_iin` |
| `organization_phone` | Телефон организации | `organization.phone` |
| `organization_bank` | Банк | `organization.bank` |
| `organization_iban` | IBAN | `organization.iban` |
| `account_number` | Лицевой счёт | `receipt.account_number` |
| `client_name` | Абонент | `receipt.client_name` |
| `client_address` | Адрес абонента | регион + улица + дом + кв. (как v1) |
| `period` | Период | `billingPeriod.label` либо `receipt.period` |
| `service_name` | Услуга | `receipt.utility_service_name` |
| `billing_type` | Тип расчёта | человекочитаемая метка (как v1) |
| `receipt_number` | Номер квитанции | `receipt.receipt_number` |
| `issued_date` | Дата квитанции | `issued_at` в `d.m.Y` |
| `generated_at` | Сформирована | текущие дата-время `d.m.Y H:i` |
| `volume` | Объём | как v1 (без незначащих нулей) |
| `unit` | Единица измерения | `utilityService.unit_of_measurement` |
| `tariff_price` | Тариф | деньги `0.00 KZT` |
| `amount` | Сумма | деньги |
| `paid_amount` | Оплачено | деньги |
| `adjustment_amount` | Корректировка | деньги |
| `opening_balance` | Долг (нач. сальдо) | деньги |
| `closing_balance` | Конечное сальдо | деньги |
| `amount_due` | К оплате | `max(0, closing_balance)`, деньги |
| `copy_title` | Название экземпляра | «Для организации» / «Для абонента» / «Предпросмотр» |

Форматирование денег/объёма — те же приватные хелперы, что сейчас в `BuildReceiptPrintViewData` (переносятся/переиспользуются). Пустые значения → `-`.

**Составные** (вставляются готовым безопасным HTML-фрагментом, генерируются нашими партиалами):

| Ключ | Название | Содержимое |
| --- | --- | --- |
| `meters_table` | Таблица счётчиков | существующий партиал таблицы показаний со строкой «Итого» |
| `logo` | Логотип | `<img>` с URL логотипа организации; пусто, если файл не загружен |
| `qr` | QR-код | `<img>` с URL QR; пусто, если не загружен |

## Рендерер

`App\Support\ReceiptTemplateRenderer::render(string $html, array $values, array $fragments): string`

- Плейсхолдеры ищутся регулярным выражением `\{\{\s*([a-z0-9_]+)\s*\}\}`.
- Ключ из `$values` → значение через `e()` (экранирование).
- Ключ из `$fragments` → HTML-фрагмент как есть (фрагменты генерируем только мы).
- Неизвестный ключ → пустая строка.

Подстановка выполняется **после** санитизации HTML (санитизируется шаблон, а не результат), фрагменты — наши и безопасные, скалярные значения экранированы.

## Санитизация

`App\Support\ReceiptTemplateHtmlSanitizer` на базе `symfony/html-sanitizer`, вызывается **при сохранении** (в БД попадает только чистый HTML) и повторно при рендере печати (защита от записей, попавших в БД в обход страницы).

- Разрешённые теги: `div, section, header, footer, p, span, h1–h6, strong, em, u, s, small, br, hr, table, thead, tbody, tfoot, tr, td, th, ul, ol, li, dl, dt, dd, img`.
- Разрешённые атрибуты: `class`, `style`, у таблиц `colspan/rowspan`, у `img` — `src, alt, width, height`.
- `img src`: допускаются только относительные пути `/storage/...`; прочие источники вырезаются. Плейсхолдеры в атрибутах не поддерживаются (санитайзер кодирует фигурные скобки в URL): `{{logo}}`/`{{qr}}` ставятся в шаблон как самостоятельные плейсхолдеры-текст и разворачиваются рендерером в готовый `<img>` целиком.
- Скрипты, `on*`-атрибуты, `iframe/object/embed/form/input/svg/link/meta` — вычищаются.

CSS (`css` колонка) фильтруется отдельным простым фильтром: удаляются `@import`, `url(...)`, `expression(`, `behavior:`, `javascript:`. CSS вставляется один раз на печатную страницу в `<style>` (шаблон один на организацию; массовая печать всегда в рамках одной организации, конфликтов нет).

Лимиты: `html` ≤ 64 КБ, `css` ≤ 32 КБ — валидация при сохранении с русским сообщением об ошибке.

## Дефолтный шаблон

`resources/receipt-templates/default.html` и `default.css` — статические файлы, воспроизводящие текущую квитанцию (шапка, абонент+реквизиты в две колонки, `{{meters_table}}`, итоги «Долг/Оплачено/К оплате», всё через `{{переменные}}`). Читаются классом `App\Support\ReceiptTemplateDefaults` (новая версия: методы `html(): string`, `css(): string`; старое блочное содержимое удаляется).

Используются: (а) печатью, когда у организации нет записи или `html = null`; (б) редактором как стартовое содержимое; (в) кнопкой «Сбросить к стандартному».

## Печать

`BuildReceiptPrintViewData::handle(Receipt $receipt)` (параметр-конфиг v1 убирается) возвращает:

- `renderedCopies` — массив `copy_title → готовый HTML` (рендер шаблона для каждого экземпляра; количество копий — из `copies_per_page`);
- `templateCss` — отфильтрованный CSS;
- `copiesPerPage`;
- `receipt`, `generatedAt` — как сейчас.

`print-copy.blade.php` упрощается: `<article class="receipt-copy" data-receipt-copy="{{ $copyTitle }}">{!! $renderedCopy !!}</article>` (HTML уже санитизирован и отрендерен на сервере). `print.blade.php`/`bulk-print.blade.php` выводят `<style>{!! $templateCss !!}</style>` (один раз) и цикл по `renderedCopies`; класс `receipt-sheet-single` при одной копии — как сейчас. Печатный каркас (A5, `@page`, `receipt-sheet`) не меняется.

Партиалы `resources/views/receipts/blocks/*` удаляются, кроме таблицы счётчиков, которая становится фрагментом `meters_table` (партиал переезжает в `resources/views/receipts/fragments/meters-table.blade.php`). CSS-классы v1 `receipt-font-*`, `receipt-density-*`, `receipt-no-borders` удаляются из `receipt.css` (управление видом теперь внутри шаблона).

## Страница-конструктор

`ReceiptTemplatePage` переделывается:

- **Редактор GrapesJS** занимает основную область (контейнер с `wire:ignore`). npm-пакет `grapesjs`; JS-модуль `resources/js/receipt-template-editor.js` (входной файл Vite), инициализация: `storageManager: false`, русские подписи, стартовый контент — сохранённый `html`/`css` либо дефолт.
- **Палитра блоков**: категория «Переменные» (чип на каждую скалярную переменную с русским названием), «Элементы» — Текст, Заголовок, Две колонки, Разделитель, Таблица счётчиков (`{{meters_table}}`), Логотип (`{{logo}}`), QR (`{{qr}}`), готовые фрагменты «Реквизиты», «Абонент», «Итоги» (HTML-заготовки с переменными).
- **Форма рядом с редактором** (Filament, как v1): `copies_per_page` (1/2), FileUpload логотипа и QR (с существующей проверкой принадлежности пути организации — переиспользуется без изменений).
- **Кнопки**: «Сохранить» (JS забирает `editor.getHtml()`/`editor.getCss()` → Livewire → санитизация → запись), «Предпросмотр» (модал/панель: рендер текущего несохранённого HTML на последней квитанции организации или демо-данных — механика демо-квитанции v1 переиспользуется), «Сбросить к стандартному» (с подтверждением: `html/css = null`, файлы удаляются — как v1).
- Доступ и tenant-изоляция — без изменений (v1).

В канве редактора плейсхолдеры видны как текст `{{key}}` внутри чипов с русской подписью — точный WYSIWYG значений даёт «Предпросмотр».

## Безопасность (сводка)

- В БД — только санитизированный HTML; рендер санитизирует повторно.
- Скалярные значения экранируются; составные фрагменты генерируются только кодом проекта.
- Пути `logo_path`/`qr_path` — существующая проверка каталога организации (v1) сохраняется.
- Tenant-изоляция страницы, предпросмотра и печати — как v1.
- CSS-фильтр запрещает внешние загрузки (`@import`, `url()`).

## Тестирование

Pest:

1. Рендерер: подстановка скаляра с экранированием (`<b>` в имени абонента не исполняется), вставка фрагмента как HTML, неизвестный ключ → пустая строка, пробелы внутри скобок допустимы.
2. Санитайзер: `<script>`, `onclick`, `<iframe>`, `javascript:`-src вычищаются; разрешённые теги/атрибуты и плейсхолдеры выживают; `img src` с внешним URL вырезается, `/storage/...` и `{{logo}}` — остаются.
3. CSS-фильтр: `@import`/`url()` удаляются, обычные правила остаются.
4. Печать без записи → дефолтный шаблон, две копии, ключевые тексты нынешней квитанции на месте (регресс).
5. Печать с сохранённым шаблоном → свой HTML, переменные подставлены, `copies_per_page = 1` даёт одну копию; массовая печать применяет шаблон.
6. Страница: сохранение пишет санитизированный html/css (грязный вход очищается), лимит размера, сброс, доступ (403 контроллеру), tenant-изоляция, предпросмотр отражает несохранённый HTML.
7. Миграция: колонки `html`/`css`/`copies_per_page` появляются и работают через модель; колонка `settings` исчезает. Перенос `appearance.copies_per_page` из существующих записей v1 выполняется кодом миграции и автотестом не покрывается (тестовая БД создаётся с нуля, строк v1 в ней нет); риск ограничен — v1 в проде свежий.

Существующие тесты v1 (блочные) переписываются/удаляются вместе с функциональностью — это осознанное следствие полной замены; тесты печати по умолчанию сохраняют прежние ожидания текстов квитанции.

## Вне объёма

- Библиотека готовых шаблонов и шаблоны на услугу/тип абонента.
- Условные конструкции и циклы в шаблоне (`{{#if}}…`) — только плоские переменные и готовые фрагменты.
- Генерация QR на лету; загрузка произвольных картинок в шаблон (только логотип и QR организации).
- Браузерные (JS) автотесты GrapesJS — редактор проверяется вручную, серверная часть покрыта Pest.
